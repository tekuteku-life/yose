# 過去明細の一括編集可否と制限理由

## 追加要求と再現

R/E/I-3.64の詳細契約である。2026-10-27の追加要求は、過去の収支で編集可能なはずの項目が一括編集できない場合がある、というものである。利用データの再現と合成条件の再現は区別する。実Chromiumの合成probeでは2022年の通常支出は確定/予定とも編集できた。一方、補助情報/金融連携のない通常支出2件がgroup_idを共有すると、1件選択でもメモ/タグ以外が無効となった。共有validatorを通して保存可能な入力である。

本人の追加回答は、有効な費目の配下にあるアーカイブ済み内訳を全明細が参照し、金額は相違し、現金からクレジットカードへの口座変更と費目/内訳変更ができなかった、というものである。この条件を直接の再現観点とする。アーカイブ済み内訳そのものが無効化の原因か、group_id等の別条件かは合成操作で切り分ける。

## 適用可否

年月・過去/未来・確定/予定・締め済みだけを理由に通常項目を無効化しない。通常明細はR-3.56の共通項目を編集でき、現在値の違いや金融構造のないgroup_id共有だけで制限しない。締め月の承認/状態制約は既存の保存契約へ従う。

前払・カード自動精算・立替/回収・ポイント等の金融構造は引き続きメモ/タグだけに制限する。補助情報、分割フラグ、立替/前払口座、明示的な関連ID、他明細からの参照、同group_id内の金融役割のある明細を保護する。空のamortization_metaは旧形式の前払子として受理されるため保護を外さない。参照先未取得でも役割情報がある明細を保護する。収支種別混在は分類4項目を、振替以外を含む選択は振替先を制限する。適用チェック前と保存中の入力無効も保持する。

有効親/アーカイブ済み内訳を参照する通常収支も、有効な支払口座（現金→クレジットカードを含む）・費目・内訳へ変更できる。口座だけを変更するときは旧内訳を保持し、分類変更時は対象軸だけを変更する。金額が相違していても金額を指定しなければ各金額を保持する。既存の明示金額一括指定機能は維持する。

## 共通判定と画面

純関数で項目ごとの能力と制限原因を同じ集合から導出する。既存bulkEditableFields/buildBulkEditとDBの最新全明細による再検証も同じ判定を使い、UIだけで解除しない。制限項目の横に、どの選択明細の役割/種別条件が原因かを表示し、適用チェックへaria-describedbyで関連付ける。動的な名前・日付・IDはtextContent/escapeHtmlを使う。

現在値が共通の内訳は初期表示で復元し、アーカイブ済みなら「アーカイブ済み」と明示して現在値を確認可能とする。アーカイブ済み内訳を新しい変更先として割り当てず、有効候補へ変更できる。親変更時は内訳を明示未指定へ戻し、計上/実態を独立に扱う。元値が異なる場合も未変更の項目は原本どおり保持する。

通常共有group_idの編集は選択明細だけを変更し、未選択明細・ID・group_id・種別・関連情報を保持する。保存直前の関連役割追加は拒否し、CAS・暗号化原子保存・単調なupdated_at・再締め承認・取消/競合/ロックでの全件保持を維持する。保存/署名/APIスキーマは変更しない。

## 先行検証

単体は通常の共有group_id/別group・単件/複数・現在値相違・種別混在、真の金融役割/他明細参照/未取得参照/空の旧補助情報の保護と理由を比較する。結合は通常共有groupの保存と未選択原本保持、関連の後発追加・承認取消・暗号化失敗時の全raw不変を検査する。UIは実際の過去明細選択と金額/口座/分類の適用/保存、正当な制限の原因表示とXSSを検証する。本人の追加回答は必要に応じて設計と先行回帰へ追加する。

## 閉じる操作と履歴移動

2026-10-27の追加指摘は、キャンセルが見当たらず、戻る操作で離脱警告となる、というものである。長いフォームでも閉じる操作へ到達できるよう、一括編集専用のモーダルをヘッダー・スクロールする入力領域・操作フッターで構成する。ヘッダーの閉じるボタンとフッターの「キャンセル」「選択明細へ保存」は画面内に保持する。狭幅・低い画面でも入力領域だけをスクロールでき、操作を隠さない。

キャンセル・ヘッダー閉じる・背景クリック・Escape・ブラウザー/端末の戻るは、共通のrequestCloseで処理する。未変更なら確認せず閉じる。変更中なら一括編集の破棄確認を1回行い、拒否した場合は入力と選択を保持する。承認して閉じる場合も明細選択を保持し、DBへ書き込まない。再度開くと破棄前の入力を復元せず、原本から生成する。保存中は閉じる操作をすべて拒否し、キャンセルと保存のボタンを無効とする。保存失敗後は操作可能へ戻す。

履歴移動は既存のAppCoordinator.setupDepartureGuard/closeTopModalを共有し、独立したpopstateやbeforeunloadを追加しない。一括編集が開いている間の戻るは当該モーダルを対象とし、破棄拒否・保存中の場合も履歴のガード位置を復元してページを離脱しない。実際にページを離れる場合の離脱確認は維持する。共通のフォーカス復帰・背景inert・スクロール固定を利用し、閉じた後は元の選択画面へ戻す。認証ロック時の強制破棄は既存契約を維持する。

実Chromiumで未変更の戻る/キャンセル、変更の破棄拒否/承認、連続する戻る、保存中と失敗後、再表示、選択/全raw原本保持、フォーカス復帰を検証する。ネイティブbeforeunloadとアプリの離脱確認を区別し、一括編集中にいずれも発生しないことを確認する。画面寸法を変え、上端/下端で両操作ボタンの可視性と実クリック可能性を検査する。共通処理を使う他モーダルは既存の履歴/未保存回帰で横断確認する。

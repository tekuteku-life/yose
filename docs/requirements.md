# 「よせあつめ家計簿」要件定義書

## 本書の位置付け

本書は利用者が必要とする結果、業務規則、運用制約を定義する。画面・入出力は[外部設計書](external_design.md)、実現方式は[内部設計書](internal_design.md)、検証範囲は[設計テスト監査](design_test_audit.md)を正とする。文書の入口と旧章対応は[設計文書索引](system_design.md)である。

旧3.x/4.xの番号を維持する。同じ機能への追補は後続節の明示した修正を優先し、未実装要求は分割を理由に削除しない。未達・未検証の項目は監査へ記録し、本書の存在を実装済み/検証済みの証拠とはしない。

## 1. プロジェクト概要

正式名は「よせあつめ家計簿」、PWA短縮名は「よせあつめ」、リポジトリ識別子はyoseである。無料サービスと標準Web技術を組み合わせ、個人の家計・資産を長期保存し管理する。

- 運用の追加サーバー費用を不要にし、JSONによるデータの可搬性を保つ。
- 日常入力・閲覧・未締め集計は端末内で行い、通信断でも継続できる。
- 過去履歴の保管・月締め・同期はGoogle Apps Scriptとスプレッドシートを用いる。
- 長期利用の軽快さを目標とする。旧文書にはデータ件数/応答時間の定量SLOがないため、性能達成を断定しない。

## 2. 対象と境界

利用者は複数端末で入力・閲覧・設定・バックアップ・同期を行う。PWAのローカルデータとGoogle側の保管データを区別し、端末鍵を共有設定やバックアップに含めない。同期先、鍵登録、初回認可、配布/更新の運用が必要である。実装構成と公開範囲は各設計書に定義する。

## 3. 機能要件

<a id="r-3-1"></a>
### 3.1 入力・仕訳要件（複式簿記ライクな単一レコード構造）

- 一つの明細は一つの支出・収入・口座間振替である。複数費目・立替・分割は関連付けた複数明細に分ける。
- 計上分類と実態分類を持ち、通常は同じ分類で入力し必要に応じ分離する。金額は日本円整数で記録し、税込・税抜の入力を補助する。
- カードは負債口座として扱い、立替は立替金口座への振替と回収で管理する。

<a id="r-3-2"></a>
### 3.2 定期支出と休日補正要件

- 定期ルールは開始・終了、固定/変動額、計上/実態費目、口座、月間隔、発生日、休日補正、有効状態を管理する。
- 土日と登録祝日に対して補正なし・前営業日・翌営業日を選べる。補正で月を跨いでも本来の計上月を保持する。
- 月初/起動時の当月予定生成、同一ルールと計上月の二重生成防止、固定額の発生日到来時の自動確定を要求する。起動自動生成・到来自動確定は現実装と差があるため、削除せず監査の未達項目とする。

<a id="r-3-3"></a>
### 3.3 年払い・まとめ払いの分割計上要件（前払費用の月次償却）

- 年払い等を前払費用口座で管理し、支払総額の振替1件とNか月分の費用明細を関連付けて生成する。
- 当月を確定、将来月を予定とし、分割額の余りを初月へ集約して総額を一致させる。

<a id="r-3-4"></a>
### 3.4 集計・グラフ表示・月締め要件

- 締め時点の残高と未締め確定明細から現在残高、予定を加えた予測残高を表示する。予定表示と分類軸を切り替えられる。
- 口座・費目は追加、名称変更、並び替え、アーカイブと復元を可能にし、過去参照を壊さない。並び替え等の全操作の実装/検証状況は監査で区別する。
- 月締めで月別履歴と残高・月次集計を保存し、締め済み明細の変更は確認後に影響月以降を再計算する。未確定・金額未入力の扱いは3.43に従う。

<a id="r-3-5"></a>
### 3.5 資産口座の統合要件（投資・有価証券口座の一本化）

- 投資・証券・積立等を通常口座に統合する。外部資産の別管理を避け、拠出を口座間振替として記録する。

<a id="r-3-6"></a>
### 3.6 設定マスタ編集UI要件

- 口座・費目・中項目・定期ルールを画面から追加・編集・アーカイブ/復元できる。各設定は一意な識別子を持ち、欠落・重複でデータを失わない。
- 祝日は個別追加/削除でき、年別にまとめて初期表示を折り畳む。口座の初期残高・種別・資産/負債・表示順、定期ルールの周期等を管理する要求を保持する。

<a id="r-3-7"></a>
### 3.7 取引明細のタッチ編集・遡及更新要件

- 最近の入力と期間内明細から編集し、種別・日付・金額・両口座・両分類・メモ・タグ・確定/予定を変更できる。
- 削除は履歴を保つ論理削除とする。締め済みの変更・削除は再締め確認を経て残高・集計にも反映する。

<a id="r-3-8"></a>
### 3.8 祝日データの一括インポート要件

- 2014〜2028年の祝日プリセットをオフラインで取り込める。日付一覧・CSV・JSONの外部データも正規化・重複排除して登録できる。
- オンライン祝日APIから取得でき、通信失敗や無効データを利用者へ通知する。

<a id="r-3-9"></a>
### 3.9 ポイント払い・相殺取引要件

- ポイント専用口座からの支出と自己負担を分ける方式、および購入総額支出とポイント相殺収入を記帳する方式を提供する。
- 関連明細を対応付け、一覧でポイント併用と識別できる。

<a id="r-3-10"></a>
### 3.10 多粒度集計（日別・月別・年別）および資産残高・推移表示要件

- 流動資産・投資資産・負債と純資産を区別し、収支分析と資産分析を切り替えられる。
- 日別は選択月の日ごと、月別は選択年12か月、年別は取得済み履歴の年ごとの推移を表とグラフで確認できる。

<a id="r-3-11"></a>
### 3.11 設定マスタのGAS統合同期要件

- 共有設定と明細を通常の差分同期で双方向に統合する。設定の保存は画面へ即時反映し、通信は背景で行う。
- 設定だけの強制送信/全取得ボタンを要求せず、競合解決と端末固有設定の保持は3.44に従う。

<a id="r-3-12"></a>
### 3.12 取引種別の統合と入力モードの調和

- 取引種別と入力モードは双方向に連動し、通常・立替・回収・前払分割・ポイントの入力欄を適切に切り替える。

<a id="r-3-13"></a>
### 3.13 PWA強制バージョンチェックおよび自動・手動アップデート要件

- オンライン起動時と手動操作で最新版を確認し、更新の有無・オフライン・通信/形式エラーを通知する。
- 利用者の承認後にキャッシュを更新して再読込でき、現在版も表示する。キャッシュによる旧版残留を防ぐ。

<a id="r-3-14"></a>
### 3.14 年間予算・貯蓄目標および消化進捗の可視化要件

- 年度ごとに年間支出予算、目標貯蓄額、目標貯蓄率と費目別予算を設定し、月割目安・内訳合計との差額を確認できる。
- 前年の確定実績と締め済み集計から初期値を試算する。金額は100万円以上を1万円、1万円以上を千円、未満を百円単位へ四捨五入し、貯蓄率は非負整数%へ丸める。
- 多数費目を検索・スクロールして編集できる。年間支出・貯蓄額・率の達成率、残額、経過月に対する順調/注意/超過、費目別消化、累積推移と均等ペースを確認できる。

<a id="r-3-15"></a>
### 3.15 バックアップJSONインポート時の非破壊・差分マージ（ORマージ）要件

- 既定インポートは非破壊の差分マージであり、ファイルにない手元データを削除しない。明細は同一IDの更新日時で新しい方を採用し同時刻は手元を保持する。
- 設定は新しいIDを追加し、同じ費目の中項目・祝日・未設定年度等を重複なく統合する。締め済み月集計は月キーでマージする。
- 追加・更新等の結果を通知し、不正JSON・型/参照の問題は原本を維持して拒否する。全置換は3.45の明示承認が必要である。

<a id="r-3-16"></a>
### 3.16 集計・グラフ画面における迅速年月選択（年月ピッカー）要件

- 前後月/年の移動に加え、年月指定から任意期間へ直接移動し、集計と明細の対象期間を揃える。

<a id="r-3-17"></a>
### 3.17 集計分類・実態分類の軸切替UI表記統一要件

- 分類軸の表示は「計上分類ベース」と「実態分類ベース」に統一し、初期状態と切替後を明示する。

<a id="r-3-18"></a>
### 3.18 タグのチップUIおよび集計・検索・グラフ表示要件

- 新規・編集ともタグを候補から選択またはEnter/カンマ等で確定し、個別のチップとして追加・削除できる。重複タグを作らない。
- タグごとの金額集計・比較表示と明細検索を提供する。

<a id="r-3-19"></a>
### 3.19 メモ入力サジェスチョンおよび費目・中項目の自動連動補完要件

- 過去のメモを候補として提示し、採用時は対応する有効な計上費目・中項目を補完する。同じ分類指定中は実態にも反映する。

<a id="r-3-20"></a>
### 3.20 立替払い未回収リストおよびワンクリック返済精算要件

- 未削除・未精算の立替金を日付・相手/メモ・金額付きで表示し、回収操作で指定受取口座への返済明細と元明細の精算状態を一括更新する。
- 回収明細のタグは「立替回収」1個、メモは「立替回収」とする。元明細のタグ・メモを保持し、二重精算を拒否する。

<a id="r-3-21"></a>
### 3.21 クレジットカード締め日・口座引き落とし日設定および自動引き落とし相殺要件

- カード口座ごとに締め日、引落日、引落月のずれ、引落元口座を設定する。
- 引落日到来時に請求周期内の確定済み支出から振替を作成し、カード負債を相殺する。二重生成や金額未入力の予定取り込みを防ぐ。

<a id="r-3-22"></a>
### 3.22 分割計上取引（Installment / Prepaid Amortization）の一括連動更新要件

- 前払親/子の編集では必要に応じグループの金額・期間・口座・分類等を連動更新する。単独編集も可能とする。
- 金額変更時の再按分と初月の余りを保持し、メモだけの変更で既存の総額・分類を破壊しない。

<a id="r-3-23"></a>
### 3.23 計上分類×実態分類のクロス集計（マトリクス/ピボット）要件

- 対象期間の計上費目×実態費目の金額を行列で表示し、空セル0・行合計・列合計・総合計を確認できる。
- 行/列から明細へ絞り込む要求を保持する。クリック経路の実装/テスト不足は監査へ明示する。

<a id="r-3-24"></a>
### 3.24 ダークテーマ対応（システム追従・ライト・ダーク）要件

- OS追従・ライト・ダークを切り替え、設定を保持する。画面・ネイティブ入力・グラフの配色を整合させる。

<a id="r-3-25"></a>
### 3.25 金額入力欄の簡易電卓機能統合要件（四則演算・8%・10%・税抜統合）

- 入力・編集から四則演算、数字/小数、クリア、1文字削除、計算実行を使える。外税8%/10%と内税抽出、切捨て/四捨五入に対応する。
- 適用時だけ対象金額と税計算過程を反映し、取消では元入力を保持する。

<a id="r-3-26"></a>
### 3.26 各種データ種別ごとのJSONエクスポート & 自動判別インポート（データポータビリティ強化）要件

- 全データ・明細・マスタ・年間予算・残高スナップショットの5形式を、人間可読なJSONで個別出力できる。スキーマ版・種別・出力日時を付ける。
- 各形式と生の明細配列を入力時に判別し、既定の差分マージまたは明示した完全取込を行う。対象種別と結果件数を通知する。

<a id="r-3-27"></a>
### 3.27 費目別推移・内訳のドーナツグラフ可視化要件

- 費目別内訳を一覧と構成比ドーナツで確認できる。費目別の時間推移は3.47に従う。

<a id="r-3-28"></a>
### 3.28 各種ドーナツグラフのタッチ・ホバー時ツールチップへのパーセント（構成比）表示追加要件

- 構成比グラフのホバー/タッチで項目名、金額、全体に対する割合を確認できる。

<a id="r-3-29"></a>
### 3.29 明細一覧の表示階層刷新（費目・中項目メイン、メモ・タグ補助表示）要件

- 明細は費目・中項目を主情報、メモ・タグを補助情報として階層表示し、ポイント等の状態を識別できる。費目・メモ・タグ・日付の情報ブロックは左側から表示し、一括選択チェックがある行も中央へ寄せない。金額は右側へ揃える。

<a id="r-3-30"></a>
### 3.30 明細一覧のマルチフィルタリング（費目・タグ・キーワード・状態による絞り込み）要件

- 種別・費目・口座・タグ・キーワード等を複合指定し、対象期間の明細を絞り込める。0件と解除を分かりやすく示す。

<a id="r-3-31"></a>
### 3.31 中項目を選択しない（費目のみ指定）選択肢の追加要件

- 費目だけを指定して中項目を未指定にできる。新規・編集の未指定表現を統一し、保存/再表示で未指定を保持する。

<a id="r-3-32"></a>
### 3.32 スマートフォンにおけるメモ・タグ入力欄のフォーカスアウト時サジェスト非表示制御要件

- 候補欄は選択操作を妨げず、入力欄外への移動・タップ等で閉じる。スマートフォンで候補が残り続けない。

<a id="r-3-33"></a>
### 3.33 取引入力完了時のトースト通知（完了ポップアップ）表示要件

- 登録・修正の保存完了を通知し、最近の入力と集計へ反映する。失敗を成功として通知しない。

<a id="r-3-34"></a>
### 3.34 口座種別への負債「ローン (`loan`)」の追加要件および負債残高表記の統一

- ローン口座を負債として扱い、資産・純資産と区別して表示する。カードとローンの負債表示を統一する。

<a id="r-3-35"></a>
### 3.35 口座種別への「保険 (`insurance`)」追加（定期出費ルール・満期日の同時設定）要件

- 保険口座に満期日・満期額、保険料・支払日・口座・費目を設定し、対応する定期支出を生成/更新する。アーカイブ時は定期支出も無効にする。

<a id="r-3-36"></a>
### 3.36 集計・グラフタブの3タブ分割（収支 / 予算・実績 / 資産）および各タブ専用表示の整理要件

- 入力・収支・予算実績・資産・設定の5タブを分ける。分析タブでは専用KPIとカードだけを表示し、日/月/年の集計対象期間を整合させる。

<a id="r-3-37"></a>
### 3.37 各画面（収支・予算・資産・設定）における各ペイン（カード）の折りたたみ（表示/非表示）切替要件

- 各カードを表示/非表示に切り替え、端末内で状態を保持する。タイトルバー全体の操作は3.45に従う。

<a id="r-3-38"></a>
### 3.38 収支タブの口座別・費目別・タグ別集計項目タッチによる明細一覧へのドリルダウン連動要件

- 費目・タグ・口座から明細へ絞り込む。資産/予算からは収支の明細へ移り、一覧を展開する。

<a id="r-3-39"></a>
### 3.39 ヘッドレスChrome実ブラウザUIテストによる網羅的品質保証とUI/UX・安全性不具合の恒久的修正要件

- ブラウザの実操作で初期化・入力・設定反映・XSS・アーカイブ・期間集計・ドリルダウン・初回再ロックを回帰検証する。
- グラフライブラリの遅延/欠落でも起動やテーマ変更を中断せず、データを確認できる。

<a id="r-3-40"></a>
### 3.40 入力サジェストUI制御・クレカ引落口座連携表示・集計粒度別明細表示およびページネーション要件

- メモ・タグ候補は入力欄直下で絞り込み、選択・外部操作・Escapeで閉じる。カード設定は引落元口座を初期表示し、締め/引落条件も一覧で確認できる。
- 年/月/日で明細期間を切り替え、多数明細はページ単位で閲覧する。

<a id="r-3-41"></a>
### 3.41 静的型チェック自動検証（check:types）および集計・設定全機能網羅UIテスト拡充（予定トグル・軸切替・年次予算・テーマ）要件

- 構文・タブインデント・静的型を自動検査し、予定表示・分類軸・予算・テーマ・空状態・期間移動をブラウザで検証する。
- テスト通過だけで設計網羅を断定せず、実assert・未検証環境・カバレッジを区別する。

<a id="r-3-42"></a>
### 3.42 UI回帰テストに基づく入力・編集・一覧・インポート境界の整合性

- 入力/編集/削除・一覧・設定・取込の境界で、日付/金額/型/参照を検証し不正データや未完了処理で画面を壊さない。
- 入力方式を切り替えても選択可能な設定を保持し、遅い応答で新しい選択を戻さない。確定/予定・日付と計上月・0と未入力を区別する。

<a id="r-3-43"></a>
### 3.43 パスキー互換性・日常操作・双方向同期の改善

- 通常パスキーを登録/認証し、PRF対応時はパスキーだけでDBを解除する。非対応時と復旧にはPINを用いる。更新・戻るで離脱を確認し、承認しない限り入力を失わない。
- 金額未入力は確認後に予定として登録し、明示0と区別する。資産推移は月/年/期間指定/すべてを選択できる。タブは横スワイプでも移動できる。
- 差分同期は両方向を統合する。未確定月締めは対象版を確認し、金額未入力を締めず、締め済み変更では再締めを確認して実行する。

<a id="r-3-44"></a>
### 3.44 モバイル編集・アーカイブ保守・マスタ統合同期

- スマートフォンのタブを1行・横スクロールとする。編集のタグ/候補操作を新規と揃え、保存・取消・削除を適切に配置する。
- 編集の戻る/閉じる/Escapeは未保存変更を確認し、モーダル背景の操作とスクロールを抑止する。候補採用時は入力途中の文字を破棄する。
- アーカイブ参照明細を設定内で確認・移行できる。設定を即時反映して背景同期を示し、同期中・同期済み・未同期・競合待ちを区別する。

<a id="r-3-44-1"></a>
### 3.44.1 共有マスタの背景同期補足

- 同期は同時送信を抑止し、保存中の追加変更を再送待ちにする。再PIN解除で購読を重複させず、端末固有の鍵・表示設定を共有しない。

<a id="r-3-44-2"></a>
### 3.44.2 設定競合の確認取消と確認待ち

- 競合の両側を比較し、全手元・全サーバー・項目別から採用値を選択できる。取消は確認待ちとして再開できる。
- 確認中に原本/鍵/版が変われば古い選択で上書きしない。既に完了した別段階は巻き戻さず、同一受信候補の不整合な部分適用を防ぐ。

<a id="r-3-45"></a>
### 3.45 セクション操作・編集分類・完全インポート

- セクションはタイトルバー全体とキーボードで開閉できる。明細編集は両親子分類が一致するとき共有ON、相違時は独立のままとする。
- 完全インポートは選択JSONの種別全体を置き換え、対象と削除・サーバー反映を明示し、正確なマジックワードで最終承認する。取消/ロック/原本変更/途中失敗で部分置換しない。
- 置換後の変更・削除は次回同期でサーバーにも反映し、版競合・再送・後続編集を保護する。

<a id="r-3-46"></a>
### 3.46 全更新境界のデータ整合性

- 通常追加/編集/生成/削除/マスタ/差分・完全取込/同期/月締めの全更新境界に同じ型・必須値・参照・収支種別・重複規則を適用する。
- 通常操作は既存の問題を悪化させず修復を許可し、完全置換は候補全体を検証する。新しいアーカイブ参照は禁止し、履歴の参照は保持する。
- 認証変更・並行編集・暗号化失敗・多ストア更新途中失敗で原本を守る。データを推測して削除/付替えしない。

<a id="r-3-47"></a>
### 3.47 アーカイブ明細のメンテナンス更新と費目推移

- アーカイブ保守は最新の取得済みデータを再読取し、参照明細がある設定だけを件数付きで提示する。選択元の一覧と更新状態を明示し、旧応答を拒否する。
- 期間内に参照明細があればアーカイブ費目/口座も絞込候補に含める。計上/実態と振替先を含み、予定非表示や他filterで候補を狭めない。
- 費目支出を日/月/年の推移で表示する。締め済み月集計との重複を防ぎ、日分解できない履歴を推測しない。取得範囲・空状態・代替表を示す。

<a id="r-3-48"></a>
### 3.48 定期ルール・入力切替・精算の操作整合性（1.12.1）

- 定期ルールの新規/一致編集は分類共有ON、相違編集はOFFとする。両軸・親子・明示未指定を保持し、振替では分類を保存しない。
- 中項目未指定を通常明細と統一する。全モーダルの戻るは最上位を閉じ、マスタの変更破棄・保存中・失敗再試行・遅延処理を安全に扱う。
- 直接精算のタグ/メモを簡潔にし、通常から前払の空総額へ金額を引き継ぐ。入力済み総額・他の入力を上書きしない。

## 4. 非機能・セキュリティ・運用要件

<a id="r-4-1"></a>
### 4.1 同期契機

非表示/バックグラウンド移行、オンライン復帰、手動操作、月締めを契機に未同期データを保護して同期する。成功した送信版だけを同期済みとし、通信失敗/競合で原本を失わない。

<a id="r-4-2"></a>
### 4.2 通信契約と到達性

静的配布元からGoogleログインCookieを用いずGASへ通信する。公開到達性とデータ操作の署名認証を区別し、疎通GETで金融データや鍵を返さない。本番CORS/リダイレクト/公開権限の到達性は模擬テストだけで保証しない。

<a id="r-4-3"></a>
### 4.3 データ保護と署名認証

端末内の明細・マスタ・集計本文を暗号化し、秘密鍵を平文永続化しない。署名・時刻検証で不正な操作を拒否し、鍵なしで金融データを表示/同期しない。暗号化対象外の検索メタデータやサーバー平文JSONは内部設計に明記する。

<a id="r-4-4"></a>
### 4.4 パスキーとPIN

通常WebAuthnの署名検証とPRFによる鍵束の復号でPIN入力を省略する。PRF非対応または旧登録はPIN経路を保持し、再登録で対応を有効にする。暗号鍵の端末復元とパスキーの提供者同期を区別する。

<a id="r-4-5"></a>
### 4.5 鍵管理の操作分離

PIN/ロック、Ed25519公開鍵の登録・表示等、パスキー登録・解除を設定で明確に区別する。確認なしの意図しない鍵消去や再生成を防ぐ。

<a id="r-4-6"></a>
### 4.6 UI構造の保守性

画面状態と各機能の責務を分離し、初期化の重複・古い応答・認証変更で不整合を生じさせない。分割された実装はオフライン配布にも含める。

<a id="r-4-7"></a>
### 4.7 計算・永続化構造の保守性

計算・保存・検証・取込・同期の責務を分離し、共有規則を一元化する。保存/計算の公開APIとオフライン動作を維持する。

<a id="r-4-8"></a>
### 4.8 旧PRF形式からの移行

正しいPINで復号成功を確認してから旧情報を削除し、同じ暗号鍵・署名鍵・明細を保持する。旧credentialは通常パスキーとして再登録し、別端末の暗号鍵復元とパスキー同期を区別する。

## 5. 受入と追跡

外部設計の操作・出力と内部設計の計算・保存・通信の両方を、既存テストの実assertへ対応付ける。単体・結合・システム・実ブラウザUIを区別する。実Chart.js・OSの認証器・実Google環境・実機の操作は模擬実行とは別の確認である。

全対象ファイルLine/Branch各97%以上という品質基準、および設計・先行テスト・独立レビューの手順は[開発プロセス](development_process.md)に従う。定量性能、色の視認性、実サービスの到達性等の未検証を「テスト合格」で補わない。

review66で未達となった全対象の是正は[受入是正設計](coverage_acceptance.md)に従い、既存の金融・認証・互換データ契約を保った不足観点の検査と不要処理の除去によって行う。基準・計測対象・計算方法を変更して受入としない。

<a id="r-3-49"></a>
### 3.49 パスキー単独解除・日本語種別・既存回収の関連付け（1.13.0）

- PRF対応パスキー登録時は解除中のDMKと署名鍵をPRF由来鍵で暗号化し端末内に保存する。以後は署名検証・鍵束復号・既存データ検証の成功によってPIN入力なしで解除する。非対応・取消・失敗はPINで解除でき、秘密鍵やPINを平文保存しない。
- 初期設定・再ロック・再起動・BFCache復帰では全画面認証だけを操作対象とし、背景へのキーボードフォーカス移動を防ぐ。解除UIを全画面へ統一する。
- 収支明細と最近の入力の仕訳種別は「収入」「支出」「振替」で表示し、保存値はincome/expense/transferを維持する。
- 元立替・回収の編集画面双方から既存明細を関連付け・解除できる。同額正数・金額確定・確定済みの明細を1対1で結び、未回収候補から除く。関連付けでは新規明細を生成しない。
- 回収として手入力した収入も候補に含め、明示確認によって立替金口座から受取口座への振替に変更する。収入集計と立替金残高への影響、過去月の再締めを確認する。メモ・タグ・ID・日付・グループは保持する。
- 回収削除・関連解除で元立替を再び未回収にする。関連中に関係を壊す編集や元削除は解除を案内して拒否する。旧精算済み履歴は維持し、関連先未取得と候補なしを画面で区別する。

<a id="r-3-55"></a>
### 3.55 取得済みデータのメタ情報

設定タブに取得済み業務データの明細件数、削除済み件数、確定/予定件数、最古/最新取引日、月平均/年平均件数、UTF-8 JSONサイズ（バイト）を表示する。平均の分母は最古から最新の取引日までの暦月数/暦年数（空の月・年を含む）である。サイズは共有項目へ射影したmaster_config・summary_snapshot・削除済みを含むtransactionsの論理JSONであり、鍵・端末設定・IndexedDBの物理使用量・未取得のサーバー明細は含まない。

<a id="r-3-56"></a>
### 3.56 明細の選択と一括編集

収支の明細一覧でチェック選択し、選択数を確認して一括編集する。選択範囲は現在の絞込結果内でページをまたげる。絞込結果から外れた明細の選択は解除する。全選択は表示ページだけである。変更する項目を明示選択し、無選択項目・ID・種別・関連情報を保持する。共通する項目とは全選択明細に適用可能な項目を指し、現在値が異なる項目も変更指定できる。

メモ・タグは全種別共通である。通常明細では日付・計上月・状態・金額・支払/受取口座を編集でき、同じ収支種別なら分類、振替だけなら振替先も編集できる。前払・カード自動精算・立替分割/回収連携・ポイント分割等の関連明細を含む場合、金融条件の一括変更を無効にする。全件を原本比較付きで検証・原子的保存する。締め済み月は元月と移動先の再月締め承認を必要とし、取消・競合・認証変更では部分保存しない。

<a id="r-3-57"></a>
### 3.57 ふるさと納税枠

税・控除タブに給与・社会保険料・生命保険・住宅ローン・ふるさと納税の詳細設定と計算をまとめる。予算タブは選択年に寄附実績がある場合の寄附合計・上限・残額と設定への導線を表示する。寄附は任意の費目・内訳を指定でき、旧データはタグ/計上費目・中項目の名称が「ふるさと納税」と一致する従来判定を維持する。取引日が属する年の確定一覧・合計と予定額を分離する。前年の取得済み確定収入は参考値として表示し、手取収入を給与年収/課税所得とみなさない。

必要な項目を任意の計上費目・内訳へ割り当て、未記録の項目を手入力する。給与・社会保険料・その他控除から上限概算を導出する。生命保険は年間保険料と契約区分から控除額、住宅ローンは年末残高等から税額控除額を求め、併用方式による影響を区別する。未入力は0と断定せず未算出とし、不足項目を示す。通知書から所得割額/特例税率を直接指定する方法も保持する。寄附を任意の費目・内訳へ割り当てられるよう、設定は寄附登録前から表示する。計算範囲・年別規則・保存と検証の詳細は[ふるさと納税計算設計](furusato_calculation.md)を正本とする。

<a id="r-3-58"></a>
### 3.58 投資口座の取得原価・評価額推移

投資額は保有商品の取得原価である。口座・日付別に証券会社の保有商品一覧等で確認した取得原価の合計を記録/訂正/削除する。取得原価は0以上の円整数であり、預り金、累計入出金、配当、売却代金、口座残高から推定しない。売買後は残存する保有商品の取得原価を記録する。取得原価の系列は各時点以前の直近記録値であり、次の記録まで据え置く旨を示す。記録前は初期残高0の場合も未記録とする。旧差引拠出額を取得原価へ読み替えない。

評価額は従来どおり投資口座全体（預り金を含む）の日末評価額である。取得原価は保有商品のみ、評価額は口座全体であることを画面に明示し、差額を含み損益として表示しない。評価記録と、それ以後の確定入出金による参考推移であり、市場価格の変動を自動反映しない。同日取引を再加算しない。観測後明細の完全性を確認できない場合は評価を推定せず帳簿残高を使う。取得原価は記録値なので明細完全性に依存しない。評価を資産推移・投資合計・純資産へ一貫適用し、二重加算しない。記録は暗号化・共有同期・バックアップ対象である。

<a id="r-3-59"></a>
### 3.59 推移グラフの操作・収入内訳・年間目標連動

選択期間に応じて折れ線の丸だけを間引き、Ctrl+スクロール/2本指で金額軸を拡大縮小できる。描画する項目を選択し、収支の費目別推移・内訳を収入にも切り替えられる。年間目標は貯蓄率/貯蓄額/支出予算の基準から現在の取得済み年間収入を用いて逆算し、目標額・進捗・推移へ一貫適用する。詳細は[グラフ・年間目標設計](chart_budget_improvements.md)を正本とする。

<a id="r-3-61"></a>
## R-3.61 表示の階層と明細ページ操作

データ情報は件数・サイズ・取引日期間・月平均・年平均を箇条書きで示し、対象範囲の注意書きを小さい文字で余白を置いて下に表示する。税・控除は入力の見出し、補足説明、採用額、計算結果を文字サイズ・太さ・背景・余白で区別する。計算式・保存形式は変更しない。

明細一覧は上下に前後ボタンとページ情報、下側にページ番号指定のプルダウンを持つ。複数ページがある場合だけ表示し、上下の無効状態と現在ページを同期する。明示的なページ移動後だけ、固定ヘッダーに隠れず上側のページ操作欄と明細先頭を確認できる位置へスクロールする。フィルター・同期等の再描画ではスクロールしない。0件時は1ページに戻し、件数減少時は最終ページへ丸める。

収支種別・状態・口座・費目・タグ・検索語のフィルターには可視ラベルを付ける。収支種別の選択肢は「すべての種別」「収入」「支出」「振替」であり、既存のAND条件とページ初期化を維持する。320px幅でも操作欄の横はみ出しを生じさせない。

<a id="r-4-9"></a>
## R-4.9 GAS認証の是正

公開APIでの初回鍵登録を禁止し、所有者が管理画面で事前設定した正規の安全な公開鍵による署名だけを認可する。時刻は正の安全な整数と±5分を要求する。再送はキャッシュに依存せず有効窓全体にわたり永続記録で拒否し、認証台帳・ロックの障害時は業務処理を中断する。詳細は[認証是正設計](gas_auth_hardening.md)である。


<a id="r-3-63"></a>
## R-3.63 資産画面の表示階層・推移の個別参照・年の一括月締め

詳細と工程再入時の契約は[資産表示・個別参照・年間月締め設計](asset_trends_annual_closing.md)を正本とする。

資産推移は表示期間・対象口座、取得原価と口座評価額の定義、補足説明、描画項目を区別する。投資評価記録は口座/日付、金額、保存操作、保存済み記録を区切り、ラベルを太字、補足を小さな文字とする。狭い画面では入力を縦に並べ、記録表の横スクロールを表の枠内に限定する。

すべての時間推移グラフで、マウス/1本指が触れた点・線・棒の系列のラベルと円金額を1件だけ表示する。通常線の途中では同じ系列の最寄り観測点を示し、金額を補間しない。取得原価の階段線は水平区間で直前の観測値を示し、次の記録値を先取りしない。非表示系列・欠測による線の空白・グラフの余白は対象外である。線が重なる場合も1系列だけを表示する。

収支の年別表示では、選択年の1〜12月を一括月締めできる。開始前に12か月すべての金額未入力を検査し、対象範囲・手元の未確定予定件数・再締め・未来月を含む場合の影響・途中失敗時の部分完了を確認する。取消時は月締めを実行しない。承認後は1月から順に既存の月締めを呼び、予定の版確認・未同期送信・サーバー応答後の確定を維持する。途中失敗時は完了月と停止月を示して後続を中止し、通信断で結果が不明な月は同期による確認を案内する。再実行では完了月も再締めする。日別/月別表示の月締めと定期予定生成は引き続き選択月が対象である。

<a id="r-3-64"></a>
## R-3.64 過去明細の一括編集可否

[一括編集可否設計](bulk_edit_eligibility.md)を正本とする。通常の過去収支はgroup_id共有だけで一括編集を制限せず、真の金融構造は保護する。項目ごとの能力と原因明細を説明し、保存側も共通判定で再検証する。

一括編集のキャンセル操作を常時表示する。戻る操作は編集中の画面を閉じる対象とし、変更破棄の拒否と保存中は画面・入力・選択を保持する。閉じるだけでは明細を変更しない。

<a id="r-3-65"></a>
## R-3.65 同期結果の業務項目表示

[明細操作改善設計](transaction_workflow_improvements.md)を正本とする。明細の送受信件数に加え、口座・費目/内訳・定期予定・祝日・年度予算/税設定・投資評価・ポイント既定・月締め情報の実変更を表示する。無変更、完了済み、未同期/未確認、競合/取消を区別する。

<a id="r-3-66"></a>
## R-3.66 明細一覧の一括削除

既存の選択集合から確認後に一括論理削除できる。選択原本・関連整合性・締め承認・認証を検証して全件原子的に保存し、失敗/取消で部分削除しない。詳細は明細操作改善設計に従う。

<a id="r-3-67"></a>
## R-3.67 入力済み予定の行内確定

金額入力済みの予定を一覧の1ボタンで確定できる。明示0円と未入力0円を区別し、他の金融内容・関連・両分類を保持する。競合/締め/認証の保存時再検査を行う。

<a id="r-3-68"></a>
## R-3.68 保存中の操作抑止と表示

開始元認証・子処理への伝播・busy所有権・保存済み応答の境界は[非同期操作設計](async_session_boundaries.md)を適用する。

明細登録/編集/一括編集の送信draftを開始時に固定し、フォームとボタンを無効化してspinner/読み上げ可能な進捗を示す。取消/失敗は入力を保持し、認証失効後の旧処理が新しい入力やbusyへ干渉しない。

<a id="r-3-69"></a>
## R-3.69 大量明細での操作応答改善

13,000件での全復号/全書換の反復とネットワーク待ちによる応答遅延を削減する。暗号・全件整合性検証・CAS・原子性を維持し、実環境と測定環境を区別して時間と処理回数を記録する。ローカル反映を同期完了待ちで拘束しない。

締め済み月の変更も承認後のローカル保存と一覧反映を先に完了し、再締め通信を背景へ回す。連続変更を阻害せず、後着応答で新しい版を戻さない。背景の失敗は保存済み未同期として保持し、非遮断表示する。

<a id="r-3-70"></a>
## R-3.70 入力済み明細の予定生成抑止

同ルールの既存明細に加え、同計上月・種別・口座・計上費目/内訳・金額の金額入力済み手入力も1対1で予定を充足する。取引日は一致条件としない。保存時の最新状態で判定し、既存明細を変更しない。

<a id="r-3-71"></a>
## R-3.71 ポイント相殺の既定分類

設定画面で相殺収入の費目/内訳を指定し、特定IDへの依存を除く。任意のポイント口座方式、旧明細、両分類を保持する。新しい任意設定は共有同期/取込/出力/GAS検証の対象とし、未設定/無効なら全件未保存で再設定を案内する。

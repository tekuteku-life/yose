# 外部・内部設計と既存テストの網羅性監査

## 結論

**既存テストが外部・内部設計を完全に網羅するとは確認できない。** 多数の入力・保存・同期・暗号・復旧に直接assertがある一方、未検証の境界/実環境と、要求に対する実装の未達が残る。全テスト合格、設計IDの対応表登録、コードの行/分岐カバレッジを別の指標として扱う。

監査基点はmain b547c13（業務コード1.12.1）である。文書分割に伴い開発プロセスのPatch規定で版を1.12.2へ揃えた。業務実装と既存テストのassertは変更せず、テストを弱めて監査結果を良くする処理は行わない。最終再実行と独立レビューは[review54](reviews/review54.md)へ記録する。

設計の一般説明/章の索引は試験単位ではない。E/Iの識別子全102件が対応表に存在することを点検するが、102件登録済みを「102件網羅済み」と呼ばない。対応表と証拠カタログを分割して管理し、同じassert一覧を複数文書へ重複転記しない。

判定は次の意味である。

- **対応あり**は記載した論点への直接assertがある状態である。全条件・全環境を保証しない。
- **部分検証**は主要経路の根拠がある一方、示した境界・異常・操作・環境が未確認の状態である。
- **未検証**は対象の振舞いを直接判定する既存assertが見当たらない状態である。
- **仕様乖離**は要求と現行実装の差である。現行を期待するテストが合格しても、旧要求の達成とは扱わない。

## 旧断定の整理

旧8.2の「乖離なし」「コードと1対1」の一括結論を廃止し、各論点の証拠へ置き換えた。旧「全DB暗号化/DevTools不可」は金融本文のローカル保存時保護と検索メタデータ・解除中メモリ・サーバー平文JSONを分け、旧「未対応署名fallback」はクライアントWeb CryptoとGAS純JS検証を分けた。これは実装修正による要件達成ではなく、保証範囲の記述修正である。

## 実行結果と限界

既存テストは単体19ファイル・結合12ファイル・システム3ファイル・UI19ファイルである。UIのdescribe数はファイル数と一致しない。再実行はNode95スイート743件すべて合格、UI20スイート299件中298件合格・1件失敗であった。失敗したケースは単独では合格したが、全体成功とは判定しない。詳細は[review54](reviews/review54.md)に記録する。

NodeのLine/Branch測定はNodeが読み込んだソースの値であり、UIコントローラーやSW本体のカバレッジを示さない。UIコマンドはCDP実行であり、ブラウザソースのcoverage収集は行わない。全対象各97%以上の基準未達と、テストの合否を別に報告する。

Node測定はLine99.40%・Branch91.14%であり、全対象ファイル各97%以上の数値ゲートは未達である。UIの失敗をskip/期待値変更で隠さず、今回は既存テストを変更しない監査結果として保持する。

### 数値ゲート不合格からのPhase 3再入

I-3.49の再計測契約を追加した。収集器は片側分岐のみの不合格、NodeとChromeの反対分岐の統合、reload前後の詳細範囲保持、未実行原本の0%、不正raw/原本不一致/報告集合欠損の拒否を直接assertする。SW原本のinstall/activate/message/fetchはVMのプラットフォーム境界fixtureでキャッシュ副作用と応答をassertし、実配備と混同しない。認証の追加観点はRSA実署名、DER異常、非対応環境、旧credential、PRF結果欠損/長さ、canonical JSON配列要素/穴である。閾値や対象を減らして合格にしない。

初回統合はNode839件合格、UI335件中330件合格であった。4件は計測器のdocument破棄/BFCache復帰による詳細欠落であり、受入成功としない。1件は前払子明細の再編集で非同期open完了前に旧hidden入力へ書くテスト同期不足であった。Phase 3へ戻り、active/対象ID/再描画済み金額/submit可視を待機して本来の再配分・単独編集assertを保持する。テーマ抽出は保存優先/OS追従/非対応media/保存読取拒否の原本VM試験と既存実ブラウザの保存後reload試験で検証する。

E-4.4/I-3.49の認証背景は、初期設定、手動ロック、再起動、BFCache復帰で実Tab/Shift+Tabを送り、背景inertと認証内循環、Escape保持、解除後の通常操作復帰をassertする。旧PINモーダルを背景キーボードの抜け道から操作する試験は追加せず、全画面へ一本化して不要経路を除去する。

収集器の追加26ケースは、sessionStorage退避後のbinding送信失敗・保存後ACK喪失・同一チャンク再送の一度だけの加算・内容不一致の拒否をassertする。context破棄による読取再試行はCDPプロトコルエラー型に限定し、同じ文字列を含むJavaScript例外が一度で失敗することを確認する。raw全記録の検証と全原本の0初期化を維持し、未実行分岐を計測器の都合で除外しない。

公開ロジックの追加境界は、日付の引数省略/祝日スカラー、マスタ省略一覧/不正移行先/祝日双方削除/古い競合情報の拒否、所有キーによる予算prototype汚染の防止、実明細優先と0円予算の計算結果を対応付ける。単体の公開API入力境界であり、実UIの操作網羅を代替しない。

長いUIスイートの時間切れは、通常操作ごとに全原本counterを複製/保存する計測負荷と切り分ける。実Node/Chromiumのprobeを反復して通常操作中に不要な記録を増やさず、closeで全呼出数を一度だけ回収することを先行assertする。reload・pagehide・BFCache・未ACK再送の既存assertを維持し、時間上限の緩和だけで成功にしない。

前払の再表示失敗は、押下と解放の間の実一覧置換によって行クリックが発火しない実装不具合として再現した。E-3.49/I-3.49へ戻り、最近/期間一覧の押下中のDOM保持・解放後の最新編集/削除・cancel/blur/認証変更の待機解除・描画世代を先行検証する。既存の1001円/3分割から400円への一括変更と単独子編集の金融assertを維持する。

候補読込中に実Escape/取消で編集を閉じ、実読取を解放しても遅延ひも付け画面が復活せず、再編集では通常どおり関連付けできることをassertする。鍵再生成の実confirm後にPINを取消/誤入力し、旧security_keys原本保持・中止/失敗通知・成功通知なしをassertする。成功通知の重複除去はAuthの保存後通知を維持する。

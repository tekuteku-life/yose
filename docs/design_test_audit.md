# 外部・内部設計と既存テストの網羅性監査

## 結論

**既存テストが外部・内部設計を完全に網羅するとは確認できない。** 多数の入力・保存・同期・暗号・復旧に直接assertがある一方、未検証の境界/実環境と、要求に対する実装の未達が残る。全テスト合格、設計IDの対応表登録、コードの行/分岐カバレッジを別の指標として扱う。

監査基点はmain b547c13（業務コード1.12.1）である。文書分割に伴い開発プロセスのPatch規定で版を1.12.2へ揃えた。業務実装と既存テストのassertは変更せず、テストを弱めて監査結果を良くする処理は行わない。最終再実行と独立レビューは[review54](reviews/review54.md)へ記録する。

設計の一般説明/章の索引は試験単位ではない。E/Iの識別子全102件が対応表に存在することを点検するが、102件登録済みを「102件網羅済み」と呼ばない。対応表と証拠カタログを分割して管理し、同じassert一覧を複数文書へ重複転記しない。

判定は次の意味である。

- **対応あり**は記載した論点への直接assertがある状態である。全条件・全環境を保証しない。
- **部分検証**は主要経路の根拠がある一方、示した境界・異常・操作・環境が未確認の状態である。
- **未検証**は対象の振舞いを直接判定する既存assertが見当たらない状態である。
- **仕様乖離**は要求と現行実装の差である。現行を期待するテストが合格しても、旧要求の達成とは扱わない。

## 旧断定の整理

旧8.2の「乖離なし」「コードと1対1」の一括結論を廃止し、各論点の証拠へ置き換えた。旧「全DB暗号化/DevTools不可」は金融本文のローカル保存時保護と検索メタデータ・解除中メモリ・サーバー平文JSONを分け、旧「未対応署名fallback」はクライアントWeb CryptoとGAS純JS検証を分けた。これは実装修正による要件達成ではなく、保証範囲の記述修正である。

## 実行結果と限界

既存テストは単体19ファイル・結合12ファイル・システム3ファイル・UI19ファイルである。UIのdescribe数はファイル数と一致しない。再実行はNode95スイート743件すべて合格、UI20スイート299件中298件合格・1件失敗であった。失敗したケースは単独では合格したが、全体成功とは判定しない。詳細は[review54](reviews/review54.md)に記録する。

NodeのLine/Branch測定はNodeが読み込んだソースの値であり、UIコントローラーやSW本体のカバレッジを示さない。UIコマンドはCDP実行であり、ブラウザソースのcoverage収集は行わない。全対象各97%以上の基準未達と、テストの合否を別に報告する。

Node測定はLine99.40%・Branch91.14%であり、全対象ファイル各97%以上の数値ゲートは未達である。UIの失敗をskip/期待値変更で隠さず、今回は既存テストを変更しない監査結果として保持する。

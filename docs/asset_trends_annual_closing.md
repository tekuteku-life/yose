# 資産表示・個別系列参照・年間月締めの設計

## 要求と工程再入

R/E/I-3.63の詳細契約である。資産画面の表示階層、すべての時間推移グラフの個別参照、収支の選択年1〜12月の一括月締めを対象とする。前回の工程順序違反を遡及的に解消したとは扱わない。既存差分は候補実装として退避し、最新origin/main 770ebf9起点のfeature/asset-trends-annual-closingでPhase 1から再評価する。未統合の複数立替一括回収022e8d2は持ち込まない。

## あるべき構成と全体影響

表示の階層は意味付きHTMLと専用CSSで表し、投資の保存イベント・DOM ID・CAS・暗号化を保持する。ChartControllerの時間推移共通描画からヒット判定を1か所へ接続し、系列選択・金額軸ズーム・テーマ・代替表を維持する。年間締めは既存close_monthを順に呼ぶ画面側の調整であり、新たなサーバーAPIや暗号/署名/保存スキーマを設けない。OAuthスコープと40,000文字の保存分割は変更しない。金額/残高/投資評価の計算式も変更しない。

## 資産画面

表示期間と対象口座を背景付きの枠へまとめ、ラベルを各入力の上へ置く。取得原価と口座評価額の意味をdt/ddで分け、市場価格の未反映と含み損益ではない旨を小さな注記とする。描画項目は区切りの下のチェック一覧である。投資記録は口座/日付、金額、保存、保存済み記録の順で見出し・余白・境界を設ける。金額の意味をaria-describedbyで入力へ結び付ける。540px以下は1列とし、長い表の横スクロールを表枠内に限定する。入力不可・保存中・エラー・未記録・旧形式の動作は既存契約を保持する。

## 個別系列の参照

収支の棒、費目/資産/予算の折れ線で、hover/touchとも最大1件を返す。日時/期間は観測点、ラベルは系列名、金額は¥付きの桁区切りであり、負数と0円を保持する。円グラフの構成比は変更しない。HTMLの外部tooltipは導入せずChart.jsのcanvas tooltipを使う。

棒はxy方向のnearest/intersectから1件を選ぶ。線は可視系列の非skip点と、実線のPath2Dの近傍を参照する。点の間引き・半径0でも参照でき、曲線・階段線・nullで途切れた区間は実描画と一致させる。線の許容幅は6論理px＋線幅の半分である。画面DPRの変換はCanvasのtransformを保存/一時解除/復元して扱う。重なりは最短距離、同距離では系列の描画順で1件を選ぶ。線途中の表示金額は同系列の最寄り観測点の値であり、補間値を作らない。空データ/全非表示/欠測/余白/領域外では表示しない。2本指のピンチをtooltipと競合させない。ロック・再描画後に旧chartを再使用せず、テーマ・ズーム・表示選択を既存のライフサイクルへ従わせる。

通常線の観測点はポインターから画面上のユークリッド距離が最小の非欠測点とし、同距離は先のインデックスを選ぶ。取得原価のstepped='before'はこの通常線の選択とは分け、水平区間ではポインターx以下で最も新しい観測点、垂直境界のxでは境界日の観測点を選ぶ。水平区間の右側で次の記録日以前の取得原価を先取りせず、日時/金額の組を保持する。境界の丸の左側も水平区間と同じ時間解釈である。

Chart.jsは描画領域外でinteraction modeを呼ばず旧activeを保持するため、Chart.js側の領域判定に加え、各時間推移chartのイベント後処理で描画領域外/2本指時にChartのactiveとtooltipのactiveを明示解除して再描画する。軸ラベル・凡例上への移動、および最初の指が領域外にある2本指の入力も対象とする。凡例の選択操作は妨げず、凡例操作で既に破棄されたchartを後処理しない。軸ラベル/凡例/ピンチへ移った実入力で旧tooltipが消えること、階段線の水平区間/境界で表示日付・金額が正しいことを回帰で直接確認する。

## 年間締めの状態と承認

年別表示では年次アクションへ切り替える。日別/月別は選択月のみである。定期予定の生成は全表示で選択月のみと明示する。年次では空の月と締め済み月も含め1〜12月を対象とする。未来月を含む場合は定期予定生成ができなくなる影響を確認画面へ明記する。

開始時に粒度・対象年/月・鍵・認証世代を保持し、読込中から処理終了まで二重起動を拒否する。対象全月を先に読み取り、削除済みを除いた金額未入力が1件でもあればclose_monthを1件も送信しない。予定は取得時の内容を月ごとに保持する。年次確認は対象範囲、手元の予定件数、予定の確定、再締め、未来月、途中失敗時の部分完了を含む。取消時は締め処理・予定確定・新しい取引生成を行わない。

承認後は各月の開始前に認証を再確認し、未同期送信→既存close_month署名要求→サーバーの予定集合/内容版検査→応答の暗号化原子保存を順に実行する。予定の追加/変更・サーバー側の未入力は既存の拒否を維持し、自動再承認しない。年送り・タブ切替で開始済みの対象年を変えない。ロック/再解除では旧処理を再開せず、旧処理による新セッションの表示更新を行わない。

成功応答を受け取った月だけを完了一覧へ追加する。失敗時は完了月と停止月を表示し、後続月を呼ばない。応答喪失やローカル保存失敗では停止月がサーバーで締め済みの可能性があるため、同期で確認してから再実行する旨を示す。再実行では同年の1月から再締めする。全体のロールバックは行わない。最終表示更新の失敗は締めの失敗と混同せず、保存済み結果を示し操作可能な状態へ戻す。

取消・金額未入力・事前読込失敗など、closeMonthの呼出開始前に終了した操作では画面再取得を行わない。既存refreshAllViewsのカード自動引落生成は取消時の副作用となるため、この終了経路へ入れない。送信を試みた後の表示更新はrefreshAllViews({generateSettlements:false})という読取専用経路を使う。省略時の既存動作は維持するが、falseではprocessCreditCardAutoSettlementsを呼ばず、既存の表示描画だけを実行する。この表示更新例外は処理内で捕捉し、締めの成功/失敗通知を保持したまま、表示だけの失敗と再表示の案内を別に通知する。ロック/世代変更後は旧処理による表示更新自体を行わない。

## セキュリティと運用境界

### 最終表示更新中の認証失効

Phase 5の実UIで、最終更新の口座読取を保留し、ロック/再解除して新口座名を描画した後に旧読取を解放すると旧名が戻ることを再現した。既存authGenerationとDB鍵を閉じ込めた認証有効関数を共有し、handleCloseMonthからrefreshAllViews({generateSettlements:false,isSessionValid})へ渡す。通常のrefreshも開始時の認証を捕捉する。追加の認証世代カウンターは導入しない。

refreshAllViewsは各描画の開始前と完了後に検査し、描画側も各非同期読取後・内部状態/DOM反映直前に同じ関数を検査する。直接呼出も開始時の認証を捕捉し、親の有効関数を新セッションへ取り直さない。横展開先はTxInputの口座/分類/中項目・タグ/メモ候補・未回収一覧、Settingsのmetadata/pending/URL/config/credentialと末尾Master、BackupImportの保留表示、Master一覧、SyncBadge、Maintenanceである。既存TxList/Summary/Insights/Budget/Furusatoの鍵・描画世代・対象年ガードは保持し、親の有効関数と合成する。候補等はローカル変数へ読んで有効時だけ状態へ反映する。

失効した旧catch/finallyは新セッションへ通知・見出し・ボタン・loadingを反映しない。認証失効時に締めbusyを同期的に破棄し、旧完了が新しい締めのbusyを解除しないよう既存authGenerationで所有を確認する。SyncBadgeの直接呼出による同期中/ロック中表示は保持する。MaintenanceはrefreshGenerationと認証の双方でcatch/finallyを保護する。最終口座読取中の実ロック/再解除に加え、分類・候補・Settings配下・badge・Maintenanceの後着結果が新表示/内部状態を変えず後続を開始しない先行回帰を設ける。

メモ履歴の分類自動反映も同じ非同期描画に含める。TagMemoInputが文字列を渡す経路と入力イベントの両方で、開始時の認証・対象メモ値を捕捉し、マスタ読取後、各中項目読取後のDOM反映前、catch通知前に検査する。文字列経路でも現在のinput-memoと捕捉値を比較し、別メモへの変更やロック/再解除後は旧履歴を適用しない。両updateSubcategoriesへ開始元の有効関数を渡す。新セッションの計上/実態分類とメモ入力を保持する先行実UIを追加する。

既存の認証/署名/予定内容版検査/同期commitを迂回しない。口座名・系列名はtextContent/escapeHtmlかcanvas文字描画を使う。金融内容と秘密鍵を新たなストレージへ保存せず、通信先も増やさない。新モジュールをSW事前キャッシュへ含め、5箇所とlockfileの版を1.20.1へ揃える（一括編集のキャンセル是正を含む）。公開GASの実耐久性・CORS/OAuth・Google割当、実端末の指操作と更新配信はローカル試験と区別する。

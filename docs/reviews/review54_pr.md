## 概要 / 背景 (Background)

要件、画面仕様、JSON、内部構造、運用手順が一つのsystem_design.mdに混在し、旧対応表の「乖離なし」が現行実装と実assertの範囲を示していなかった。責務を三文書へ分割し、外部64項目・内部38項目について既存テストの確認範囲と不足を再監査する。

## 変更内容 (Changes)

### 1. 設計上の変更・判断 (Design Decisions)

- 要件定義書は旧3.x50節・4.x8節の要求を保持する。未実装の自動定期処理等を分割の理由で削除しない。
- 外部設計は画面・操作・確認/エラー・公開通信・JSON契約・文脈/ユースケース/遷移を扱う。内部設計は計算・永続化・暗号・同期・排他/復旧と詳細図を扱う。
- system_design.mdは入口と旧章対応へ縮小し、旧レビューの参照アンカーを保持する。README/開発プロセス/PRテンプレートを新構成へ更新する。
- 全102設計IDに実it名・位置・assert・不足を対応付ける。対応表への登録、実行合格、コードカバレッジを混同しない。
- 旧ERDと現行補助metaの差、JSON例の省略参照、暗号化/再送防御/実環境の保証範囲を明示する。業務実装と既存テストは変更せず、文書改定の版規定で1.12.2へ同期する。

### 2. 対象ファイル一覧 (Modified / Added / Deleted Files)

- 新規: `docs/requirements.md`、`docs/external_design.md`、`docs/internal_design.md`、`docs/design_test_audit.md`、review54のレビュー/証拠記録である。
- 変更: `docs/system_design.md`、`docs/development_process.md`、`docs/ui_test_audit.md`、README、PRテンプレート、規定版情報とlockである。
- 削除: 旧一括文書の重複正本と、根拠を示さない「乖離なし/全て対応」という一括断定である。旧全文はGit履歴に保持する。

# Review 52: 期間内アーカイブ設定の明細フィルター

## Phase 1: 設計

原因は、明細一覧が期間元明細を取得していても、費目・口座候補を有効マスタだけから生成していることである。候補生成を一覧描画の共通箇所 `TransactionListController.populateFilterDropdowns` に集約したまま、有効マスタと期間内未削除明細に参照されるアーカイブマスタの和集合とする。

- 費目参照は計上 `category_id` と実態 `actual_category_id` の両方である。口座参照は出金元 `account_id` と振替先 `to_account_id` の両方である。
- 候補判定はステータス・予定表示・口座・費目・タグ・検索語の絞込み前の期間元明細に対して行う。0円・予定明細も対象であり、削除明細は対象外である。
- 有効設定は取引0件でも表示する。アーカイブ設定は期間内に参照が1件以上あるものだけを表示する。マスタ順を維持し、名前・IDはHTMLエスケープする。
- 選択中の設定が候補に残る限り維持し、期間変更・削除等で候補から消えた場合は `all` に戻す。複数フィルターによって表示0件になっても他の候補は消えない。
- 月別と年別は計上月 `target_month`、日別は取引日 `date` で期間を判定する。年跨ぎ休日繰延でも年別の集計・費目内訳と明細候補を一致させる。
- 非同期描画には描画世代を設け、DB読取中に期間・条件が変わった場合、古い描画が最新の候補・明細を上書きしない。
- ドリルダウンは既存共通処理を通し、アーカイブ費目も選択・表示できる。編集・入力の新規選択肢へは追加せず、明細表示のみを変更する。
- 金額・明細データの変更、サーバー処理、暗号化境界の変更はない。

## Phase 3: テスト観点

新規実ブラウザテスト `test/ui/archived_filters.test.js` で次を検証する。

1. 月内の計上・実態費目および出金元・振替先口座が候補に入り、未使用・期間外・削除のみのアーカイブ設定が入らない。有効設定は0件でも残る。
2. アーカイブ費目・口座を選択して該当明細へ絞れる。ドリルダウンでもアーカイブ費目の選択・明細表示が成立する。
3. 0円・予定明細の参照が予定OFF・別フィルター・検索0件でも候補に残る。
4. 月・年・日の切替で期間内候補が変わる。年跨ぎ休日繰延で取引日と計上年が異なる明細も計上年に含める。期間内に残る選択は維持し、対象がなくなった選択は `all` へ戻す。
5. 月移動の古いDB応答を意図的に保留し、最新期間の描画完了後に解放しても候補・明細が巻き戻らない。
6. 名前にHTML風文字列を含む設定を候補へ安全に表示する。

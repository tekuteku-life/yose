# PRタイトル

fix(ui): 定期ルールの分類・戻る操作と立替精算・前払入力を修正

## 概要 / 背景 (Background)

定期ルールの追加・編集で計上と実態を共通化できず、戻る操作がアプリ離脱確認になる問題を修正する。中項目未指定の表現を通常明細に揃え、立替回収リストからの精算で重複したタグ・長いメモを付与せず、通常入力から前払分割へ金額を引き継ぐ。

## 変更内容 (Changes)

### 1. 設計上の変更・判断 (Design Decisions)

- 定期ルールの新規は分類共通化ON、一致する既存分類もONとし、異なる分類はOFFで保持する。旧省略と明示nullを区別し、共有中の計上変更を両軸へ保存する。振替の分類はnullとする。
- 定期・保険・メンテナンスと候補なしの通常入力を含め、中項目未指定を「（指定なし / 費目のみ）」へ統一する。
- 戻るは最上位モーダルのclose経路を使い、マスタの未保存変更は閉じる/Escape/backで破棄確認する。保存待機・失敗・認証変更・旧応答を扱い、失敗再送では候補を毎回作り直してID重複を防ぐ。
- 直接精算の回収明細はタグ1個とメモを「立替回収」にする。手入力では利用者の指定を保持してタグを重複排除し、原本比較と一括保存を維持する。
- 通常から前払分割の空の総額へ金額を引き継ぎ、明示0と既存入力を区別する。日付・口座・分類・メモ・タグを保持する。

### 2. 対象ファイル一覧 (Modified / Added / Deleted Files)

- 新規: `test/ui/recurring_categories.test.js`、`test/ui/master_modal_navigation.test.js`、`test/ui/input_mode_settlement.test.js`、review53のレビュー記録である。
- 変更: `master_controller.js`、`coordinator.js`、`maintenance_controller.js`、`tx_input_controller.js`、`transaction_factory.js`、既存回帰テスト、設計・監査表、版情報である。
- 削除: モーダルの戻る対象の固定列挙、重複した回収ラベル付与、不自然な中項目未指定文言である。

# Phase 1・2 設計変更と独立設計レビュー記録

- 対象は設計書3.42とUIテスト調査記録である。
- レビュワーは実装担当と別のCodexサブエージェント `design_review` である。
- STRIDE・データ整合性・境界検証・副作用・変更範囲の妥当性をレビュー対象とした。

## 指摘とPhase 1への差し戻し

1. 親だけでなく有効な償却子の `amortization_meta.total_amount` も更新する規則が不足していた。金額変更時のみ全有効明細へ反映し、メモのみの編集では保持する規則と回帰テストを追加した。
2. JSON入れ子の型不正が部分保存後に画面を壊す可能性があった。配列要素・中項目・タグ・予算・スナップショットの全件事前検証と、正常・不正要素の混在時の非破壊性を追加した。
3. 締め済み・未締めが混在する前払の遡及更新が不足していた。締め済み全対象への署名付き遡及要求と後続差分同期を定義した。テストは複数要求と同期の完了を待ち、対象IDとスナップショットを確認する。
4. テストレビューでスナップショットの正規フィールド名との相違を検出した。GASの `income_total`・`expense_total` を正規形として優先し、有効な0も維持する規則を追加した。

各指摘を設計とテストへ反映したうえで独立レビューを再依頼した。最終出力は **PASS** であり、Phase 4へ進む。

## 影響範囲

UIの状態遷移・編集・HTML出力、DBのインポート前検証・前払メタデータ・引落オフセット、履歴集計、暗号セッションの呼び出し契約を対象とする。暗号アルゴリズム・GASの権限・署名プロトコルは変更しない。バグ修正としてバージョンを1.7.5へ更新し、5箇所に加えてpackage-lockのルート版も同期する。

この設計承認は最終リリースの承認ではない。既存から未達のカバレッジ97%基準はPhase 5で引き続き判定する。

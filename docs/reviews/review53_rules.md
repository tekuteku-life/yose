# Review 53 定期ルール分類と中項目文言の監査

## 対象と設計

`docs/system_design.md` 3.48および開発プロセス定義に従う。対象は定期ルール追加・編集の分類まとめ、保険の定期費目とメンテナンスを含む中項目未指定の文言である。保存スキーマ、同期、GASおよび暗号化は変更しない。

既存の定期ルール画面は計上・実態を常時別々に表示していた。通常入力と明細編集はすでに同一分類を畳む操作を持つ。保険料の定期設定は元から一組の分類を扱い、生成時に両軸へ同じ分類を設定するため、追加のチェック欄を要しない。

定期生成の実態中項目補完と同じく、実態の親が省略された場合は計上親を使い、中項目の省略時だけ同じ親の計上中項目を補完する。明示的なnullは未指定を保持し、異なる親の中項目を複写しない。補完後の分類の一致時はON、既存の不一致はOFF、新規はONである。ONからOFFへ切り替える際は、直前まで共有した最新値を独立入力の初期値として保持する。

## Phase 3 先行テストと独立レビュー

`test/ui/recurring_categories.test.js` に11件を先行追加した。新規ON、親子一致、異親、異子、明示null、旧データの省略、異親での子省略、再ON・OFF、種別変更、振替、アーカイブ保持と新規除外、および定期・保険・メンテナンスの文言を対象とする。

独立レビュワー `/root/review53_audit` のPhase 3判定はPASSである。実装前の11件はすべてREDであり、新しいチェック欄・折り畳み欄の欠如と旧文言を検出した。証跡は `/tmp/review53-rules-red.log` である。

## Phase 4 実装と横展開

定期ルールへ「実態分類を計上分類と同じにする」を追加した。ON時は計上変更を実態へ即反映し、保存時もチェック状態から両軸の値を決定する。OFF時は別々に設定し、振替の保存値は両軸ともnullとする。既存のアーカイブ設定は未変更の編集で保持し、新規候補には表示しない。

中項目未指定を定期の両軸、保険料、およびメンテナンスで通常明細の「（指定なし / 費目のみ）」へ統一した。通常入力で費目なしの場合の「なし」も横展開対象として入力担当へ引き継いだ。旧「中項目の指定はなしである」は対象ソースに残っていない。

構文・型検査はPASSである。新規11件と既存整合性UI28件の計39件はPASSした（`/tmp/review53-rules-green.log`）。

## Phase 3 再入場: 実可視性の保証

実装自己点検で、`hidden`属性だけを確認するテストでは、`.form-row { display: flex; }`がUAの非表示指定を上書きする問題を検出できないと判明した。Phase 3へ戻り、共有状態の検証へ実ブラウザの`isVisible`確認を追加した。実際に欄が表示されたままになるREDを再現した（`/tmp/review53-rules-visibility-red.log`）。独立レビュワー `/root/review53_audit` は追補観点をPASSとした。

非表示対象を通常の外枠divとし、内側にレイアウト用の`form-row`を置いた。これによりUAの非表示指定とレイアウト指定を競合させない。既存の`integrity_workflows`の独立分類操作も、同じチェックをOFFにして欄が見えることを確認してから操作する手順へ更新した。既存の中項目リセットと分類保存の検証は維持した。他のsettings/headlessの定期テストには、隠れた実態欄を直接操作する手順は存在しない。このテスト変更も独立レビュワーのPhase 3追補PASSを得た。

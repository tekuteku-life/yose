# PR草案

タイトル: `feat(workflows): 明細操作と同期表示の改善、締め済み月更新の非同期化`

## 概要 / 背景 (Background)

13,000件を超える明細で保存・同期時の全件書換えと重複復号が発生し、締め済み月の修正も再締め通信の完了まで次の操作を妨げていた。同期表示、一覧操作、予定重複生成、ポイント分類設定をR/E/I-3.65〜3.71として改善する。

## 変更内容 (Changes)

### 1. 設計上の変更・判断 (Design Decisions)

- 同期結果を実際のcommit由来の明細件数と業務項目へ分け、口座・費目/内訳・定期予定・祝日・年度予算/税設定・投資評価・ポイント既定・月締め情報の変更を方向別に表示する。部分失敗でも確定結果を保持し、並行ローカル編集を受信へ帰属しない。
- 明細一覧へ一括削除と金額入力済み予定の行内確定を追加する。原本比較・関連金融データ・締め承認・全件原子保存を維持する。
- 保存前にdraftを固定し、フォーム全体を無効化して進行表示を行う。認証失効・編集対象切替・後着処理が新しいdraftを変更しない。
- ローカル保存/表示と背景カード生成/同期を分離する。締め済み月の連続修正を末尾送信へ合流し、旧ACKによる新版の同期済み化を防ぐ。再締め後の残高も新draftを保持して反映する。
- 復号cacheを鍵世代で失効させ、認証済み暗号文だけをcloneで再利用する。全件CAS/検証を保ち、IndexedDBの明細書込は変更分だけとする。archive補助metadataも業務/baseと同時に原子保存する。
- 予定生成は同ルール明細に加え、同じ計上月・収支種別・両口座・計上費目/内訳・金額の手入力を1対1で除外する。実金融groupを充足へ流用しない。
- ポイント相殺の収入費目/内訳を共有設定の既定値とし、固定ID依存を除去する。旧データの設定不在、差分取込、完全置換を区別し、旧GASによる黙示除外を応答検証で拒否する。
- 新規端末の初回同期はDEFAULT基準を区別し、既存remoteの任意ID設定を受信する。明示変更・旧データ・空サーバー初期送信・金融参照検証を維持する。
- カバレッジ収集のmetadataを重複排除してBFCache時の容量超過を防ぐ。元schemaへの復元、ACK再送の非重複、source/map/counter検証を維持する。
- 背景マスタ受信で候補外となった選択も「利用不可」として保持する。新候補は反映し、保存時の最新参照検証は緩めない。

### 2. 対象ファイル一覧 (Modified / Added / Deleted Files)

- 新規: `js/logic/sync_changes.js`、`js/ui/form_busy.js`、`js/ui/sync_result.js`、各層の回帰試験、詳細設計/レビュー/性能記録である。
- 変更: DB/暗号ストレージ・同期・予定/ポイント生成、入力/編集/一覧/一括操作/設定/集計/認証controller、HTML/CSS、GAS、仕様/監査、版数/SWである。
- 不要経路: 同期全体前後の明細二重読取による件数集計と、変更時の全明細clear/put経路を置き換えた。commitMasterSyncの通常返値、予定生成の配列返値、既存保存形式を維持する。

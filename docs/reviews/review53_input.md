# Review 53 入力切替・立替精算の検証記録

## 対象と原因

設計書3.48に基づく通常入力から前払分割への金額引継ぎ、直接立替精算のタグ・メモ簡素化、手入力回収の利用者入力保持、中項目未指定文言の統一である。

直接精算は入力コントローラーが元明細のタグとメモを引き継いだうえで、共通生成関数が再びシステムタグとメモ接頭辞を追加していた。直接精算呼出は固有の短いメモだけを指定し、生成関数は手入力メモを保持してタグを重複排除する責務とする。元明細の原本比較、一括保存、二重精算拒否は維持する。メモ未指定時の既定値も「立替回収」とする。

入力モード切替は金額欄を別要素として持ち、通常金額から前払総額への値複写が存在しなかった。通常から前払分割への切替時だけ、前払総額が空なら通常金額の文字列を複写する。明示0、既存総額、再切替、他モード固有金額を保護する。

## 先行テスト

- UI 8件: 実リストから直接精算した保存値・元明細保持・再精算拒否、原本並行編集時の一括拒否、手入力回収のメモとタグ、モードボタンおよび種別プルダウンからの金額・共通項目引継ぎと前払全件保存、空欄・0・既存総額・再切替、他モード固有値保持、費目候補なし時の中項目文言である。
- Node 1件追加: 利用者メモの保持、タグの重複排除、入力配列非破壊、既定メモ・タグである。既存2箇所のメモ期待値も新仕様へ更新する。
- 既存の同時直接精算テスト、立替・前払ワークフロー、保存失敗・整合性テストも回帰対象とする。

## 横展開調査

- 中項目文言検索では、マスタ画面2箇所とメンテナンス1箇所の「中項目の指定はなしである」、通常入力の費目候補なし分岐2箇所の「なし」を確認した。すべて既存レコード画面と同じ「（指定なし / 費目のみ）」に統一する。他の「口座指定なし」等は異なる意味のため対象外である。
- 各入力モードの固有金額は表示切替時に消去されず、それぞれDOM内で保持される。共通の日付、口座、分類、メモ、タグも共有される。収入から支出系モードへの変更は既存仕様どおり費目種別を切り替え、選択可能な費目だけ保持する。
- 前払生成関数は総額から支払親と月次子の金額を配分する。引継ぎテストはDOM表示だけでなく親総額・子合計・両軸分類・タグ・メモ・税メタデータまで確認する。
- 仕様書3.20に古い回収フォーム補完の記載が残る点を主担当へ報告した。

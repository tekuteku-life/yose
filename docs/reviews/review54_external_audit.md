# 外部設計と既存テストの対応監査（review54）

対象は1.12.1のmain b547c13（本文基点e817c6f）に存在するテストである。テストを追加・変更せず、it本文のassert、操作とfixtureの実装を読み、[外部設計書](../external_design.md)の全識別見出しに対応付けた。実行合否はroot担当のreview54に記録し、本書の「検証」は静的に確認した既存assertの範囲を意味する。

## 判定方法と環境境界

- 部分検証: 対応するassertはあるが、正常/異常/境界/取消/並行/環境の少なくとも一部を保証しない状態である。
- 仕様乖離: 旧要求と現行実装の振舞いが異なる状態である。テストが現行を期待して通過しても要求達成とはしない。
- 未検証: 該当操作・外部環境を直接確かめるassertを確認できない状態である。表の不足欄で明示する。
- 行番号は既存テストのit開始行であり、テンプレート名はパラメーターケース全体を指す。関連ファイルが存在するだけでは根拠にしない。
- [CDP driver](../../test/helpers/cdp_driver.js#L25)はChart.jsを描画しないstubへ置換する。chart設定/データ/破棄のassertは実Chartのピクセル・凡例配置・ホバー表示の保証ではない。
- 専用WebAuthn UIケースはChromium仮想CTAP2を使う。通常fixtureの認証器成功モックと区別し、1Password・OS実認証器の保存/更新UIは未検証とする。
- GAS試験はMockGasEnvironment/customFetchによるローカル実行である。匿名manifestとHTTPオプションのassertは実GoogleのCORS/公開設定/Android通信成功の保証ではない。
- 年月inputへの値設定とブラウザ標準pickerの実ポップアップ選択、Blob内容とOSファイル保存、模擬BFCacheイベントと実BFCache復帰を区別する。

## 優先して補う観点

| 優先 | 不足/乖離 | 次に確定すること |
|---|---|---|
| 高 | 定期起動生成・固定額到来自動確定 | 要求を維持するなら日付/休日/月またぎ/既生成/競合/締め済み拒否の先行テストを完成し、生成/確定経路を設計する。要求を変更する場合は利用者の意図を確認して要件側から改訂する |
| 中 | 並び替えUI、クロス行/列クリック | 旧要求の未達として保持する。導入する操作と対象範囲を設計してからUI回帰を追加する |
| 中 | 祝日プリセット・オンライン取得 | 旧要求の2014〜2028全体を再現可能な期待値と照合し、取得成功/HTTP/非JSON/切断と反映前状態を検証する |
| 中 | 3種ドーナツの実ツールチップ、全グラフ外観 | 実Chart.jsを用いるローカルE2Eで描画/タッチ/hoverを検証し、stub検証と結果を分ける |
| 中 | 鍵管理ボタン/通知/ローン表示 | コピー/再生成/登録/解除、全保存モードの成功・失敗トーストと自動消去、負債通貨符号を直接assertする |
| 実環境 | 1Password、Android通信、iOS/Android picker・IME、PWA更新 | 実認証器/公開GAS/実OSでのみ確かめられる受入項目として環境と結果を記録する。既存モック合格で代用しない |

本監査は新たな実装依頼を勝手に実行するものではない。未達を隠す要件削除、assertの弱体化、網羅したとの一括判定は行わない。全外部設計の完全網羅は確認できず、上表の部分検証と仕様乖離を残す結論である。

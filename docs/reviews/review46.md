# 1.8.0 日常操作改善・通常パスキー移行の設計と検証

対象日は2026年10月21日（日本時間）、ブランチは `feature/passkey-and-daily-usability` である。前回の修正を含むコミット `0dfd26a` を基点としている。前回の検証記録は[review45](review45.md)である。

## 要望と実装の対応

| 要望 | 動作・設計判断 | 主な対象 |
| --- | --- | --- |
| 1Passwordへ保存できるPRFなしパスキー | 利用者が選択したPIN併用方式である。通常WebAuthnで登録・署名検証を行い、DB復号にはPINを使用する。PRF要求・平文vaultフォールバック・旧共有bundle生成を廃止した。 | crypto、webauthn、auth、settings |
| 更新・戻るの確認 | 更新・離脱はブラウザ標準確認、戻るは履歴ガードと確認を使用する。取消では鍵を消去しない。実離脱・BFCache復帰では再認証する。アプリ更新の二重確認を避ける。 | coordinator、settings |
| 金額未入力で予定登録 | 全入力モードで空欄の確認後に0円・planned・amount_pending付きで保存する。明示的な0とは区別する。未入力の回収で元立替を精算済みにしない。 | tx_input、transaction_factory、tx_list、tx_edit、DB |
| 資産推移の月・年・期間指定・すべて | 独立カードへ折れ線グラフを追加した。未来・予定を除き、履歴月末残高を基点に確定明細を加算する。未取得期間を偽の0円で埋めない。年送りと収支粒度を分離した。 | aggregator、summary、chart、index |
| 横スワイプ | 5タブを隣接移動する。縦操作・入力欄・ボタン・チャート・横スクロール・モーダル・画面端・複数指等を除外し、両端では循環しない。 | coordinator |
| 差分同期の双方向化 | 排他区間内で取得・CASマージ・送信・再取得を行う。全アーカイブ・削除・新しい版も取得し、同時刻はローカル未同期版を優先する。マスタの専用送受信は既存の設定操作で行う。 | sync、DB、GAS、sync_status |
| 未確定あり月締めのコーション | 予定件数を確認し、承認した集合と全内容の版をGASへ渡す。別端末での追加・変更があれば無変更で拒否する。未入力金額は締めない。成功前にローカルだけ確定しない。 | summary、sync、GAS |
| 締め済み明細変更の確認・再締め | 保存前に影響する締め月をまとめて確認し、取消は全変更を中止する。承認後は既存遡及更新でアーカイブと後続残高を再計算する。後から別端末の締めが判明した場合は、手元の未同期変更を保持して再確認する。 | coordinator、tx_edit、tx_input、sync、GAS |

詳細な契約は[設計3.43](../system_design.md#343-パスキー互換性日常操作双方向同期の改善)、パスキー移行は設計4.4・4.8である。旧説明との矛盾を置換した。暗号化DBのschema_versionは2のままであり、PIN暗号化パッケージと既存DMK・Ed25519鍵を維持する。

## Phase 1・2 設計レビュー

独立したCodexサブエージェント `design_review`・`ui_gap_review` がレビューした。初回指摘は、予定の件数・承認フラグだけでは同時更新を防げないこと、遡及経路で未入力予定が検査を迂回すること、前払の未入力解除範囲、別端末が先に締めた場合の未承認送信であった。

承認を予定ID・正規化した全内容へ結び付け、締め済み月の有効明細は入力済み確定のみとした。前払の金額再配分では全親子の未入力フラグを解除し、メモだけの変更と単独編集の他明細では保持する。GASも全保存先・移動元先の締め月承認を検査する。未承認変更は手元に残し、手動同期で確認する。定期予定の締め済み月への生成は説明して拒否する。

両者の再設計レビュー出力はPASSであった。

## Phase 3 テスト先行と切り分け

- 初回の新規Nodeテスト26件・UIテスト13件は製品未修正で全件失敗した。
- テストレビュー後のNode41件も製品未修正で全件失敗した。追加したUI境界13件は3件合格・10件失敗であった。
- 廃止したPRF暗号・共有bundle・署名を検証しない旧WebAuthnの7テストは、標準WebAuthnの署名検証15件、実ブラウザの仮想認証器、旧vault移行テストへ置換した。無関係な暗号化データの不正形式検証は維持した。
- 従来の空金額拒否5件は、新仕様の「予定登録を取り消せば入力保持」へ変更した。既存の遡及・月締めシナリオには明示的な再締め承認・予定の版承認を追加した。
- 署名後の改変だけでは個別の検査がなくても失敗するため、不正challenge・origin・type・RP hash・UP/UVを署名前に設定して正しく署名するfixtureへ強化した。
- 資産は純資産・負債・投資・振替・未来予定除外・欠損履歴・4期間の異なるラベルと値・不正期間での表示保持を検証する。
- 離脱は実beforeunloadの取消・承認、戻るの取消・承認、BFCache復帰を検証する。タッチは実CDP操作と除外条件のイベント検証を併用する。

両者のテスト再レビュー出力はPASSとなってから実装した。

## 検証境界と受入状態

- Chromiumの標準WebAuthnはCDPの実仮想認証器で登録・認証を検証する。1Password拡張そのものの保管庫への保存操作は未検証であり、保存先選択UIの表示を保証しない。実環境では設定のパスキー登録から保存先を選び、再ロック後の認証とPIN解除を確認する必要がある。
- beforeunloadの文言・表示可否とモバイルOSによる強制終了はブラウザの制約に従う。未保存入力の自動復元機能を追加したものではない。
- Chart.jsは既存のオフラインスタブを使う。系列・日付・残高は検証するが、実ライブラリの描画品質・実機タッチは保証外である。
- GASはモック環境で本体処理・署名・集計・アーカイブを検証する。本番のデータやデプロイは操作していない。新しい閉月承認・全アーカイブ取得の契約を使うため、リリース時にはGASも更新する必要がある。
- 全対象ファイルのLine・Branch各97%以上という数値ゲートは、前回から未達である。テスト通過・コードレビューPASSと最終受入を混同せず、基準を緩和しない。最終受入前のコミット・PR発行・本番反映は実施しない。

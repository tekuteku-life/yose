# バックグラウンド差分同期の実装・検証記録

## 対象

- 作業ブランチは`feature/background-sync`である。開始時に取得した`origin/main`は`086347a0f717e001c729f0acd2b7200dd6d00e72`である。
- 対象要件はR-4.1、R-4.3、E-4.1である。設計の正本は[バックグラウンド同期設計](../background_sync.md)である。
- バージョンは後方互換の機能追加として1.22.0とし、5箇所を同期した。GAS実装・データ形式・暗号形式は変更していない。

## 実装上の判断と自己点検

- インストール済みPWAで通常の双方向同期を開始時から別スコープのService Workerへ委譲する。Workerに画面制御権を与えず、既存のキャッシュWorkerを維持する。
- Workerは一時的なメモリDBと解除済みCryptoKeyを使用し、実IndexedDBを開かない。`waitUntil`で多段通信全体の寿命を延長し、120秒で取消す。秘密鍵・復号鍵・平文本文を永続化せず、完了/失敗/取消で参照と復号キャッシュを解放する。
- 端末への反映は元セッションと全業務ストアの期待値を用いる原子的更新である。同期中の編集・ロック・Manager交換で古い結果を反映しない。送信済み要求のサーバー側取消までは保証しない。
- Worker準備失敗だけで画面内同期へ戻し、送信開始後の応答不明では無条件再試行しない。競合/再月締めを自動承認せず、画面復帰後に同じ試行の件数・変更IDを保持して確認付き同期へ移る。
- 完全インポートは送信前のサーバー基準版の永続化を必要とする。Worker終了で基準版が失われて競合保護を破る構成を避け、送信待ちがある同期は従来経路に限定した。GASの実原本を用い、受理済み応答喪失後も基準版を保持して再送できることを検証した。
- 新方式に不要な永続キュー、平文の鍵保存、任意時刻の無認証再試行は追加していない。
- 画面内同期への切替で試行を終了すると、待機中の自動マスタ同期が割り込み、要求した同期が`already_syncing`で見送られる問題を追加テストで再現した。同じ試行を引き継いで解消し、古い切替処理の終了が次のWorker取消ハンドルを消さないことも回帰テストで検証した。

最終証跡は`/tmp/yose-background-coverage-release.log`、`/tmp/yose-coverage-YvLhg0/manifest.json`および同ディレクトリの`raw/`である。集計結果は`coverage/coverage-summary.json`、`coverage/source-manifest.json`、`coverage/execution.json`であり、`nodePassed`・`uiPassed`はともに`true`である。

初回のサンドボックス内`node --test`はファイル単位の成功しか報告せず、個別assertの実行証拠として採用していない。同じテストを許可された環境で再実行し、個別の合格件数を取得した。

全体計測は、未検証の初期化経路の追加、および切替時の競合是正のため、それぞれ途中で停止してやり直した。途中の測定値を最終結果へ混在させず、是正後の固定ソースによる単一の公式実行だけを受入判定へ使用する。

追加4ケース後のNode全件再実行は1,859件合格であった。同時点の統合計測ではUI 1,209件中1,208件合格、`security_delete_native67.test.js`が起動待ち5秒で失敗した。末尾traceは`waitForReady → navigate → openBrowser → beforeEach`であり、認証鍵削除の検証本体へは到達していない。同一計測条件の単独再実行は1件合格であったが、それだけで全体失敗を解消扱いにしていない。

起動待ちだけがCDP設定上限（標準10秒）と異なる固定5秒になっていたため、`waitForReady`の既定上限を`commandTimeoutMs`に統一した。準備完了の判定、操作対象、ネイティブdelete成功ゲート、abortと全ストア保持のassertは変更していない。ブラウザ起動が遅れた根因を製品の削除処理と断定せず、他テストを並行診断せずに全体を再計測する。

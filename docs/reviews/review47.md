# 1.9.0 モバイル操作・編集・アーカイブ保守・統合同期

対象日は2026年10月21日（日本時間）である。ブランチは `feature/mobile-editor-and-master-maintenance` であり、既存変更が統合された `main` の `72ed664` を基点とする。設計は[system_design 3.44](../system_design.md#344-モバイル編集アーカイブ保守マスタ統合同期)である。

## 要望と対応

| 要望 | 仕様と確認観点 |
| --- | --- |
| スマホのタブ折返し | タブを1行固定・横スクロールとし、ボタンの縮小と文書全体の横溢れを防止する。画面スワイプとは区別する。 |
| 編集タグのチップ化 | 新規と編集を共通部品へ統一し、削除・重複排除・IME・候補選択を検証する。 |
| 編集操作の配置 | 削除を別段へ分離し、キャンセル左・保存右とする。 |
| 編集中に戻る | 編集画面を閉じる。変更があれば破棄を確認し、取消では入力・履歴を保持する。Escapeと閉じるも同じ経路である。 |
| 背景のスクロール・操作 | モーダル表示中の背景をinert化し、スクロール位置を固定・復元する。電卓等のネストと認証ロックも考慮する。 |
| 候補選択時の途中文字 | タグ・メモの候補選択で途中文字を破棄する。ポインタだけでなくTab移動からの選択も検証する。 |
| アーカイブ参照の保守 | 設定内に取得済み明細一覧と一括移行を設ける。計上・実態分類と支払・振替先口座を検出し、有効な同種別設定へ移行する。 |
| マスタ変更の即時反映 | ローカル保存後に画面を更新し、背後で同期する。通信中の再編集・失敗でも端末内の版を保持する。 |
| 同期中の表示 | 共通の進行状態をヘッダーへ表示し、重複した手動実行を防止する。再認証後も購読する。 |
| 同期操作の統合と通信失敗 | 明細・共有マスタを差分同期へ統合し、専用送信・取得ボタンを廃止する。競合は確認して解決し、到達失敗・HTTP・非JSON・タイムアウトを区別する。 |

口座の初期残高と定期ルールは明細移行では変更しない。移行先の口座は同じ種別・資産区分、費目は同じ収支種別、中項目は有効費目の配下へ限定する。振替元先の同一化、削除明細の移行、無効先への保存を拒否する。

## 設計・テスト・独立レビュー

[独立レビュー記録](review47_audit.md)、[編集領域記録](review47_editor.md)、[同期領域記録](review47_sync.md)に詳細を記録する。実装とは別の `independent_review` が各領域の設計とテスト観点を審査した。指摘があった場合は設計または先行テストへ戻って再審査する。

保守は単体16件と実ブラウザ6件を先行した。ブラウザ実行は未実装DOMで6件失敗、単体は未実装モジュールで失敗を確認した。独立レビューによる追加観点を反映してテスト承認後に実装した。

## 手戻りと切り分け

- 保守の移行前比較が移行後の分類で比較され、確認中の中項目変更を見逃す実装不具合を独立レビューで検出した。原本変更の単体回帰を追加し17件中1件のREDを確認した。設計の全内容比較規約を維持し、対象IDから抽出した原本を比較してから原子的に保存するよう修正した。修正後の単体17件・UI6件は合格である。
- GAS統合では費目移行から署名付き通信・アーカイブ更新・締め集計再計算まで検証した。最初の期待値はカテゴリ集計を数値としていたが、既存仕様の `{ total, by_subcategory }` に合わせて `total` を検証するようテストを是正した。
- 編集の候補へのキーボード移動、認証ロックと背景inertの競合、同期のオンライン復帰時の排他、応答本文待機のタイムアウト、再認証後の進行状態購読は、独立レビューから先行テストへ差し戻して検証を追加した。
- GASマスタ更新は基点版の比較を必須とした。既存テストの初期設定も新契約に合わせて更新し、通信上の失敗とfixture不備を区別する。

## 検証境界

ブラウザUIは実Chromium/CDPの隔離環境で検証する。タブ幅・スクロール・inert・履歴・DOMと入力は検証対象であるが、実スマホ・本番GAS・実Googleアカウントには接続しない。Chart.jsの実描画と実機パスキーは本変更の検証対象外である。

利用者環境の `fetch error` は本番の通信ログを取得していないため原因確定・本番解消を宣言しない。応答を隠す `no-cors` は採用しない。到達失敗の案内に接続・公開権限・デプロイ済み `/exec` URLを含める。リリースにはGAS側も更新する必要がある。

既存から未達の全対象ファイルLine・Branch各97%以上という受入基準は緩和しない。最終測定とコードレビューの判定は別に記録する。コミット・PR発行・本番反映は未実施である。

- タブ欄を1行固定・横スクロールへ統一した。

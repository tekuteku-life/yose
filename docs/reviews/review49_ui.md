# Review 49 設定競合の比較・解決画面

## 設計

- `MasterConflictController.resolve(details, validateChoices = null)` は競合一覧を表示し、競合IDごとの `local` / `remote` 選択辞書、または取消を表す `false` を返すPromiseである。設定・明細の書込みは同期層だけが担当し、画面は選択結果だけを返す。
- 各競合は日本語ラベル、手元の値、サーバーの値、採用する版の選択欄を持つ。選択欄は初期状態を「選択する」、選択肢を「手元を採用する」「サーバーを採用する」とする。大画面では左右比較、狭い画面でも同じ項目内で両値を比較できる配置とする。
- 全項目を手元／サーバーにする補助操作を設ける。選択を未選択へ戻すことも可能である。すべての項目を選択するまでは解決同期ボタンを無効とし、送信直前にも全選択を検証する。
- 空文字・null・項目削除・undefinedを区別して表示する。配列とオブジェクトは件数／項目数の要約と展開可能なJSON詳細を表示する。文字列は改行を保持して表示する。既知の設定参照には各sideの名称を取得し、名称（ID: 元の値）を併記する。中項目は各sideの親費目名も示す。未知のID・null・削除・構造値は従来の実値表示を維持する。ラベル・値は `textContent` を使用し、入力由来のHTMLを解釈しない。
- 取消ボタン・閉じる・Escape・ブラウザの戻るはすべて同じ取消処理を通り、選択辞書を返さない。手元・サーバー設定を保持し、既に完了した明細同期は巻き戻さない旨を画面に記載する。
- 競合モーダルを静的HTMLの最後に配置し、既存の最前モーダル判定・背景inert・スクロール固定へ統合する。ブラウザの戻るは競合モーダルがある場合にも履歴ガード位置を復元して取消だけを行う。
- 認証ロック等による外部閉鎖も監視して取消扱いとし、保留中Promiseを残さない。再競合では新しい一覧・未選択状態で開き直す。二重resolveの場合は前回を取消して新しい一覧へ置き換える。
- 参照不整合の検証と再競合検出は同期層で行う。適用時には渡されたvalidateChoicesを呼び、不整合なら具体的な設定名・項目を含む例外メッセージを画面内へ表示して閉じない。利用者が選択を修正して再実行できる。検証が非同期の場合も世代を識別し、取消・認証ロック・二重resolve後の古い完了は新しい画面へ反映しない。検証中は選択変更と二重実行を禁止し、取消は可能とする。画面は成功を先取りして設定を変更しない。

## 先行テスト観点

1. 日本語ラベル・手元／サーバー実値と、null・空文字・削除・配列・オブジェクトの区別を検証する。
2. 全手元・全サーバー・混合選択、未選択への変更による実行ボタン無効化を検証する。
3. 取消ボタン・閉じる・Escape・戻る・認証ロックがfalseを返し、設定を変更しないことを検証する。
4. 320px画面で比較内容と選択欄を操作でき、背景がinertとなることを検証する。
5. ラベルと値にHTMLを含めてもDOMを生成しないことを検証する。
6. 再競合・二重resolveで前回の選択が漏れないことを検証する。
7. 同期層との結合で参照不整合の拒否と再表示、競合解決後の再同期を検証する（同期担当と分担する）。

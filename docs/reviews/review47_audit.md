# Review 47 独立レビュー記録

## 対象と手順

モバイルタブ、取引編集、候補選択、アーカイブ設定明細の保守、マスタ即時反映、同期状態表示および手動同期の改善を対象とする。`docs/development_process.md` の Phase 2・3・5 に従い、実装担当とは別の Codex サブエージェントが設計・テスト・実装を段階ごとにレビューする。

## 初期調査

- `css/style.css` のタブボタンは `flex: 1` であり、文字列の折り返しと縮小を防ぐ指定がない。
- 取引編集のタグは新規入力とは別のカンマ区切りフィールドである。現在値の口座・費目がアーカイブ済みの場合、選択肢から消え、無関係な編集で参照を書き換える危険がある。
- 新規タグ候補は入力の blur で途中語を確定した後に候補の click が確定語を追加する。候補選択と通常のフォーカスアウトを区別する必要がある。
- 戻る操作はコーディネータの離脱ガードが一括処理している。編集を閉じる履歴動作はこのガードと統合する必要がある。
- モーダルは固定オーバーレイと内部スクロールだけであり、背景のスクロール・キーボード操作を無効化していない。
- マスタ保存はローカル保存後にネットワーク送信を待ち、全画面を再描画する。マスタ送信は全置換であり、マスタの未同期管理・版管理がない。手動双方向同期は明細のみを処理し、専用のリモート取得はローカルマスタを全置換する。
- 同期要求は既に `text/plain;charset=utf-8` を使用する。fetch error の真因は通信ログなしには確定できない。実通信不能とGASのアプリケーションエラーを分離して扱う必要がある。

## 設計・テストで確認する観点

1. タブ文字列の非改行、タブ欄のみの横スクロール、文書全体の横溢れ防止、選択タブの可視化、既存の画面横スワイプとの非干渉である。
2. タグの重複・削除・IME入力、候補選択での途中語破棄、候補以外への blur による確定、新規と編集の独立状態である。
3. 編集の正規化した初期値と現在値による変更判定、未確定タグ・電卓反映、戻る・閉じる・Escape の統一、取消時の内容保持、繰返し開閉後の履歴の非累積である。
4. 背景スクロール位置の保持、背景の inert とフォーカス復元、上下端のスクロール伝播遮断、編集上の電卓等のネストである。
5. アーカイブ参照の計上・実態大中項目、支払・振替先口座、親費目アーカイブ時の子の検出、削除明細の除外、取得済み範囲と件数の明示である。移行では有効な移行先、締め月の承認、書込前比較と全件無変更、金額・ID・グループ・未入力状態の保持を確認する。
6. マスタの base/local/remote による競合処理、同一項目衝突・削除・順序・子項目・祝日の方針、送信中の再編集を保護するACK、端末専用設定の除外、失敗後のローカル反映と再試行である。
7. 手動・自動・マスタ・月締め等に共通する同期中状態、排他、失敗時の状態復帰、未同期マスタの表示である。
8. 未設定・不正URL、GAS公開URLと配備権限、HTTPエラー、非JSON、オフライン・タイムアウト・fetch拒否の区別である。`no-cors` による結果を検証できない成功扱いは禁止する。

### Phase 5 初回実装レビューからの手戻り

1. **P1: 移行前原本の比較不足**: 保守処理は移行後の計画同士を比較していた。同じ旧費目配下の中項目だけが確認中に変更された場合、移行後の値が同一となり確認していない変更を上書きした。メモリDB実行で再現した。Phase 3へ戻り、元の参照だけを変えた回帰テストのREDを確認して再承認した。既存設計の原本比較規約に従って修正する。
2. **P2: キーボード候補選択の途中語確定**: pointerdownだけのblur抑止では、Tabで候補へ移動した場合に途中語が確定した。候補へのフォーカス移動と候補外移動を区別する設計・新規編集双方の先行テストへ戻り、再承認した。
3. **P1: モーダルからの認証ロック復帰不能**: 共通モーダルガードが認証画面もinertにするため、明示ロック・BFCache復帰時にPIN入力できなくなった。認証時のモーダル閉鎖と固定解除を設計へ追加し、両経路の先行テストのREDを確認して再承認した。
4. **P2: 編集上電卓の戻る処理**: 電卓表示中の戻るが背後の編集を閉じる。最前面の電卓だけを閉じる規約を設計へ追記し、編集内容・背景保護・次の戻る確認の先行テストを再承認した。
5. **P1: オンライン復帰の明細同期欠落**: マスタ同期が先に排他を取るため、直後の明細同期がalready_syncingで終了した。単一のオンライン同期経路と先行回帰テストを要求した。
6. **P2: 応答本文のタイムアウト不足**: fetchのヘッダー受信時にタイマーを解除するため、応答本文停止を捕捉できなかった。本文読取を含むタイムアウトと先行テストを要求した。
7. **P2: 失敗状態の非表示**: 同期失敗がtitle属性だけに格納され、差分ゼロ時に同期済と表示された。失敗の可視表示と先行UIテストを要求した。
8. **P2: 再解除後の同期状態購読欠落**: PIN再解除時はSyncManagerを再生成する一方、状態購読は初回DOM初期化時だけであった。新インスタンスへの再購読とロック再解除後のUI回帰テストを要求した。
9. **P2: 欠落親・子参照の編集時消去**: 中項目描画が親費目または中項目配列の欠落時に早期終了し、現行IDを維持できなかった。計上・実態双方の参照保持を保存後まで確認する先行UI2件を再承認した。
10. **P1: 背景同期後の入力選択初期化**: 背景同期に伴う全画面再描画が、入力中の口座・費目・中項目を先頭へ戻す。必要時だけの再描画と現在の有効選択保持の設計、遅延通信中に選択して完了後も維持する先行UIを要求した。

### 編集・同期の最終再レビュー

指摘事項は先行テストへ差し戻し、修正後に以下を再確認した。

- タグ候補はマウス・タッチ・TabとEnterの各経路で途中語を破棄し、候補外への移動では通常の確定を行う。IME変換を確定操作と混同しない。
- モーダルは最前面だけを操作可能とし、戻る・Escapeで最前面の電卓を先に閉じる。認証画面表示時は有効なモーダルだけを閉じ、MutationObserverの自己通知ループを避けて認証操作と背景の状態を復元する。
- 編集はアーカイブ済み参照・欠落した親子ID・指定なしを保持する。入力の再描画は現在の有効選択を保持し、非同期の子描画は親IDの変化を検出して古い結果を破棄する。
- マスタの共有許可リストと危険キー拒否、三者比較と競合承認、GAS基点CAS、DBのcurrentとsync_baseの原子的ACK、ACK中の再編集保持が実装されている。
- online復帰を単一の双方向同期とし、本文読取を含むタイムアウト、可視の失敗状態、再認証後の状態再購読を実装している。実際に受信合成で共有値が変化した場合だけ再描画する。
- メインタブと入力モードタブの非改行・欄内横スクロール、保守UIのフォームスタイル、バージョン1.9.0と新モジュールのSW事前キャッシュを確認した。

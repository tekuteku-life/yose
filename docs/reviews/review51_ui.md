# Review 51 UI・生成ロジック監査と修正

## Phase 1: 先行設計

対象はマスタ管理、入力・編集・精算・定期生成、予算・表示設定・JSON編集、取引生成および実態分類集計である。

- マスタのモーダル編集とJSON直編集は表示時の原本を保存し、`saveMasterConfig(config, { expectedConfig })` で比較する。DBの三方向マージにより無関係な変更は保持し、同じ項目の競合時は保存を拒否して入力内容を残し、再確認を求める。アーカイブ等の単項目操作、テーマ・折畳みは最新設定に対する `mutateMasterConfig` の純粋更新とする。
- 明細編集は表示時の原本を保存し、削除・一括変更も含め原本比較を行う。未変更のアーカイブ参照は履歴として保持できるが、新たな無効参照は保存境界で拒否する。保存失敗はダイアログで通知し、入力を保持する。
- 精算はbusy制御を行い、未削除・未精算・立替種別を確認した原本と回収明細を原子的に保存する。新規登録も連打を防ぎ、生成明細はcreateOnlyで保存する。定期生成IDはルールIDと対象月から安定に生成し、旧IDの既存予定も検出する。
- 定期編集は振替先と計上・実態の親子分類を明示して編集する。取引種別変更では対象種別の有効費目を選択し、親変更時は子を初期化する。既存アーカイブ参照は表示・維持し、新規選択には含めない。
- 生成関数と集計の実態中項目は明示null/空文字を保持する。省略時の計上分類からの補完は、実態の親費目が同じ場合に限る。ポイント利用額は総額以下であることを確認する。
- 履歴からの自動分類は現行マスタの有効性・収支種別・親子を確認し、有効な分類のみ適用する。無効候補では現在の選択を保持し、メモ文字列だけを採用する。
- 非同期保存は例外を捕捉して表示する。保存成功前にモーダルを閉じず、成功前にフォームや精算状態をリセットしない。

共通の型・日付・列挙値・参照・認証検査、DBの原子的比較更新APIは親担当である。GASおよび同期は別担当である。

# Review 52: アーカイブ設定メンテナンス

## Phase 1: 原因と設計

- 更新操作は明細とマスタを再取得するが、一覧が選択中の移行元によらず全アーカイブ参照を表示し、読み込み状態も表示しない。並行した再取得には順序保証がなく、古い応答が新しい表示を上書きし得る。
- 移行元候補は、取得済みの未削除明細が1件以上参照するアーカイブ済み設定に限定する。計上・実態の両軸、振替元・振替先、およびアーカイブ費目配下の中項目を含む。金額0円、予定、金額未入力も対象である。定期ルールや初期残高だけの参照は対象外である。
- アーカイブ設定の列挙と明細参照判定を共通の純粋関数で扱い、移行計画と候補・一覧の対象定義を一致させる。
- 一覧は選択した移行元を参照する明細だけを表示する。選択変更時にも即座に一覧と件数を更新する。候補がない場合は空表示とし、移行操作を無効にする。
- 更新は最新のマスタ・明細・取得済み過去月を再取得する。残存する移行元・移行先・中項目の選択を保持し、削除された選択は有効な先頭または未指定へ戻す。
- 更新中は更新ボタンに状態を示し、移行と選択操作を無効にする。更新ボタンは再実行可能とし、世代番号で最後に開始した読取だけを反映する。失敗は通知し、操作状態を復旧する。移行処理中の更新要求は現在の移行処理終了時の再取得に集約する。
- 一括移行の既存CAS・全件原子的保存・月締め確認・暗号境界は維持する。描画は既存同様HTMLエスケープする。サーバー・同期方式・データ形式の変更はない。

## Phase 3: 先行テスト計画

- Unit: 使用件数による候補絞り込み、0件・削除だけの設定除外、計上/実態/振替先/親アーカイブの子/0円予定の包含、特定元だけの行選択を検証する。
- UI: DBの明細・マスタ変更後の更新、選択元別の一覧と件数、候補消滅・空状態、移行先中項目保持、逆順の非同期応答、更新失敗の復旧、移行中の更新無効と終了後の再取得を検証する。
- 既存のキャンセル、月締め、マスタ/明細競合、XSSの実ブラウザ回帰を維持する。

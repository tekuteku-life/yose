# UIテスト調査・回帰検証記録

## 調査範囲と方針

対象は `docs/system_design.md`、`docs/development_process.md`、過去のレビュー記録、`index.html`、`css/style.css`、`js/`、`gas/`、`sw.js`、既存の単体・結合・システム・UIテスト、および品質検査スクリプトである。独立レビュワーの調査結果も照合した。

仕様の振る舞いを先にテストへ落とし込み、製品コード未修正で実行してテスト不備と製品不具合を切り分ける。製品不具合による失敗を、期待値変更やスキップによって隠さない。修正はテスト完成後、設計・テストの独立レビューを経て開始する。

## 既存状態

- 基準バージョンは1.7.4、開始時のコミットは `2c4de13` である。
- 単体・結合・システムテストは230件合格である。
- 既存UIテストは15件中14件合格、1件失敗である。失敗は実行日を2026年10月20日と仮定した日別テストの日時依存である。
- 既存のNodeカバレッジはLine 99.77%、Branch 90.87%である。全ファイルのLine・Branch各97%以上という品質ゲートは開始時点で未達であり、過去のレビュー42の合格表記とは一致しない。
- Nodeの測定にブラウザ内UIコードのカバレッジは含まれない。UIテストの操作数や合格数をコードカバレッジと混同しない。

## テスト側の是正

- ブラウザ日時を2026年10月20日12時（日本時間）へ固定し、日付判定を再現可能にする。日時指定はテスト専用の注入である。
- 追加テストごとに独立したChromiumブラウザコンテキストを生成し、IndexedDB・認証鍵・ストレージ・画面状態を共有しない。
- クリックはCDPのマウスイベントを使い、非表示・無効・他要素に隠れた対象の操作を拒否する。可視性は祖先の非表示も考慮する。
- 準備完了や非同期処理は条件付き待機で確認し、タイムアウト時は失敗とする。未捕捉ブラウザ例外も失敗とする。
- 確認ダイアログの取消指定をブラウザ内スタブへ確実に渡す。
- 内税計算は支払額を保持し、税額と本体価格を `tax_meta` に保持する既存の計算契約を検証する。税抜価格を支払額と取り違えたテスト期待値は修正する。
- 費目ANDフィルタの除外データには計上費目と実態費目の双方を明示する。実態費目に一致する明細を誤って除外期待しない。

## 検証境界

Chart.jsはCDNを使わないスタブであり、実ライブラリの描画品質・タッチツールチップ・実端末のレイアウトは保証範囲外である。WebAuthnは非対応・取消として扱い、実機認証器や1Password等のデバイス間同期は検証しない。GASとの署名・集計・暗号処理は既存の単体・結合テストも併用する。UIテストの外部通信はCDPで隔離し、実アカウントや本番データを操作しない。

## 1.10.0 設定競合の比較と解消

`master_conflict_resolution` は、競合値の両側比較、全手元・全サーバー・項目別選択、未選択時の無効化、型と削除の区別、参照名称とID併記、XSS、取消・戻る・Escape・認証ロック、参照不整合の修正継続、再表示と非同期の世代保護を検証する。実SyncManagerと暗号化明細を使用し、競合中ロックからPIN解除・再同期まで確認する。

`master_sync` は取消を失敗と扱わず、確認待ちを表示して再度解消できることを検証する。結合では項目別採用と非競合変更の保持、明示選択の検査、確認中のローカル・サーバー版変更、認証鍵変更、暗号化中のロック時原本保持、再受信の部分完了件数を確認する。

全体実行で見つかった既存テストの待機不足は、編集のactive・対象ID、フィルタ後の対象行、対象遡及要求、保存・ページ描画完了の条件で補正する。単独合格だけでNGを無視せず、遅延プローブで旧待機の問題を再現してから修正する。設計・先行RED・独立レビュー・最終結果は[review49](reviews/review49.md)に記録する。

# バックグラウンド同期設計

対象はR-4.1、R-4.3、E-4.1である。Androidのインストール済みPWAで開始した通常の双方向同期を、画面の凍結から独立して実行する。

`display-mode: standalone`の画面だけで有効化し、起動時にWorker登録を開始する。通常のブラウザタブは既存経路で同期する。

## 処理と安全性

- オフラインキャッシュ用`sw.js`と独立したモジュールWorkerを`js/background_sync_worker.js`、スコープ`js/`に登録する。画面の制御を奪わず、同一オリジンの画面からのメッセージだけを受け付ける。
- 画面は開始時の暗号化済みDBスナップショット、アーカイブ取得履歴、解除済みCryptoKey、GAS URLをMessageChannelで渡す。WorkerはメモリDBと既存SyncManagerを使用し、署名・検証・競合検出を共有する。実IndexedDB、鍵、平文本文をWorkerから永続化しない。
- メッセージイベントの`waitUntil`へ同期全体のPromiseを渡す。最大120秒で取消し、鍵と復号キャッシュを解放する。Background Sync APIによる永続再試行は登録しない。鍵を平文保存せずに、任意の時刻に認証を復元することはできないためである。
- Workerは結果と暗号化済み変更後スナップショットを返す。画面は元セッションを検証し、開始時の全業務ストアを期待値として既存の`replaceImportBatch`で原子的に適用する。不一致時は書込を一切行わず、最新の編集と送信待ちを維持する。
- 通信失敗前の正常受信も同じ境界で適用し、既存の部分成功表示を維持する。Workerの結果を受け取れない場合は同期済みにせず、サーバーで処理済みの場合があることを通知する。
- 競合・再月締め確認はWorkerでは承認せず結果を返す。画面が表示状態に戻ってから、既存の確認付き同期で最新状態を再取得する。
- 確認付き同期へ移る場合も同じ同期試行を引き継ぎ、確認前に反映した受信件数と業務変更IDを保持する。
- ロック・同期Manager交換でMessageChannelへ取消を送り、端末への古い結果の反映を拒否する。サーバーへ送信済みの要求の取消までは保証しない。
- 準備中の登録失敗・非対応は通信前だけ従来の画面内同期へ戻す。開始後は無条件再送しない。月締め・遡及更新・個別マスタ同期は従来経路を維持する。
- 従来経路への切替でも同じ同期試行の所有権を保ち、切替の隙間に待機中の自動マスタ同期を割り込ませない。
- 完全インポートの送信待ちがある場合は全体を従来の画面内同期で実行する。完全インポートはサーバーの基準版を送信前に端末へ永続化する必要があり、メモリ内だけで基準版を更新するとWorker終了後の再試行で他端末の編集を検出できなくなるためである。Workerの対象は通常の差分同期である。

## 検証観点

| 観点 | 層と具体的な検証 |
| --- | --- |
| 署名と多段通信 | 結合: 既存署名検証で受信→送信→再受信を検査する |
| Worker内の暗号保護 | 単体/結合: 返却する全業務本文が暗号化され、永続DBを開かないことを検査する |
| 画面凍結 | UI: 実HTTP配布・実Service Worker・CDP凍結後にサーバー側の送信受理を確認し、復帰後の同期済み反映を検査する |
| 編集/ロック競合 | 結合/UI: 遅延完了で最新DBが一切上書きされないことを検査する |
| 障害/取消/寿命 | 単体: 登録失敗、応答不明、取消、期限、鍵解放、部分成功を検査する |
| 利用者確認 | 結合/UI: Workerでは承認しないことと、復帰後に既存確認へ進むことを検査する |

Android実機でのアプリ切替、省電力設定、OSによる終了、本番GASのCORS/リダイレクトはローカルChromium試験で保証できない境界である。

UI試験は実HTTPサーバーと実Service Workerを使用する。CDPはインストール済みの表示モードを再現できないため、`matchMedia`の該当判定だけを模擬する。画面凍結、多段通信、署名、復帰後の暗号化DB反映は実処理を用いる。

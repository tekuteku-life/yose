# 非同期操作の開始元認証と所有権

本書はR/E/I-3.68の保存中操作および旧完了非干渉契約の横展開設計である。review67の最終レビューで確認した取込・同期・初期化・分析設定の同型漏れに対し、Phase 1から再審査する。データ形式・署名・GAS API・金融整合性・CAS条件は変更しない。

## 認証寿命と画面所有権

非同期操作は最初のawaitより前に開始元の認証世代・DB鍵と鍵世代を捕捉する。解除後に同じ鍵を使う場合、鍵再生成が署名鍵更新より先に認証世代だけを進める場合も旧操作を失効させる。子の読取・保存・描画へ同じ親predicateを伝播し、旧読取完了後に新しい認証を捕捉し直さない。現在の認証のエラーは表示し、期限切れのエラーは取消として扱う。

画面のbusy所有権と認証寿命は別の条件である。認証失効は保存・通知・dirty解除・新しい描画を禁止する。finallyのbusy解放は、その操作がなお同じ画面ownerを持つ場合に限り可能である。ロック・cancel・新draft・新操作への遷移はownerを変更し、旧finallyが新操作のbusyを解除することを禁止する。通常closeの後も続く背景同期は、closeによって失効するmodal ownerを認証寿命に流用しない。

DBが既に原子的commitした後の認証失効は、確定済み原本や送信待ちを巻き戻さない。旧応答による通知・新画面への描画・新操作のbusy解除だけを停止する。

## 同期と初期化

SyncManagerは任意constructor引数captureSessionを受け取る。sessionGuard生成時に一度だけproviderを呼び、返された開始元predicateを既存の署名鍵・DB鍵世代・親predicateへ合成する。predicateを評価するたびに認証を捕捉し直してはならない。Coordinatorは当該managerのidentityと現在の認証を捕捉するproviderを注入する。standalone利用では省略でき、従来の鍵・親条件を維持する。

手動・差分・マスタ・月締め・遡及・取込の各active試行は、この開始元寿命をcommit・結果metadata・遅延listenerまで保持する。queueMasterSyncは旧画面draftを持たず最新DBを読み直すため、新たな試行を始める時点の認証を捕捉する。manager生成時の世代を永続固定して、正常な鍵更新後まで失効させる実装にはしない。

finishAppInitは最初の設定読取より前に認証と初期化ownerを保持する。テーマ・pane・更新確認・各描画・起動時同期に同じ親を伝播し、旧初期化が新manager/DOMを置換しない。PIN/パスキー解除は鍵をロードする正当な世代変更を含むため、ロック時のcaptureRenderSessionをそのまま解除外側へ適用しない。認証試行ownerと、解除成功後の描画sessionを区別する。

## 分析設定と絞り込み

Insightsの投資保存、BudgetSettingsの年間予算保存、Furusatoの通知書・集計設定保存は、既存のlocal generation・draft/year条件にcaptureRenderSessionを合成する。DBのisSessionValidと保存後refreshAllViewsの親へ同じ条件を渡す。認証失効後にdirty解除・保存通知・再描画を行わない。busy解放のowner条件は既存のlocal generationである。保存開始中はbusyで同controllerの別保存を拒否し、cancelはgenerationを進めてbusyを同期解放するため、旧finallyと新保存を区別できる。通常の描画によるdraft参照交換はownerを変更しない。draft/yearの一致は保存結果を表示に採用するための条件として保持し、busy所有権とは区別する。これにより同じ認証の背景描画後もbusyを解放し、cancel後の新保存に作用しない。

Furusato.confirmLedgerはdigest開始前に認証とedit世代を捕捉し、旧digestの成功では確認tokenを採用せず、旧失敗では確認解除やエラー表示を行わない。

Summary.applyDrilldownFilterは入口で認証を捕捉し、必要なcashflow描画、明細再描画2回、pane展開の各await後に検査する。子の描画とsetPaneCollapsedには同じ親を渡す。再認証後の検索文字・状態・口座・費目・タグ・一覧・paneを旧操作が上書きしない。

## 先行試験

実Chromium・実CryptoKey・暗号化IndexedDBを用いる。実generateKeyのEd25519生成完了後を保留し、ネイティブ設定ボタンからの鍵再生成でauthGenerationだけが進み、DB鍵世代が同一であることを直接検査する。この間に旧投資・予算・税保存の実DB呼出を解放し、全raw保持、dirty維持、通知/refresh抑止、および元ownerだけのbusy解放を検査する。同じ認証で投資の保存/削除・税設定保存の待機中に通常renderを行い、draft参照が交換されても原子的保存結果とbusy解放が成立する対照を置く。帳簿digestは成功・故障の両方で旧token/エラー非反映を検査する。再認証・新保存を作った場合には、新ownerのbusyを維持する既存試験も併用する。

絞り込みは実assetsからcashflowへの描画応答を保留し、実lock/PIN解除後に新しい予定filterと検索を入力してから旧応答を解放する。開始から各子awaitまでの境界を順に検査し、新しいfilter/一覧/paneと全rawを保持する。依存の表示故障は明示的な故障modelとし、auth世代やDB状態を直接捏造しない。全gateをfinallyで解放し、実Promise完了を待つ。

取込・出力の詳細契約と先行観点は[カバレッジ受入設計](coverage_acceptance.md)の「再承認・ファイル取込・出力の開始元認証」を参照する。

認証自身のintentとCoordinator/SyncStatusの具体的なAPI・所有権設計は[認証ライフサイクル設計](auth_session_lifecycle.md)に従う。署名鍵だけが同じ認証世代内で更新される境界も開始元snapshotへ含め、PIN材料が非nullである条件は別途維持する。

無効な親を伴う入口は、進行中の正常な操作ownerを変更しない。認証/親の初期検査をowner取得・generation更新より先に行う。これはfinishAppInitだけでなく、登録のswitchInputModeにも適用する。無効要求の採用を拒否しても、そのgeneration更新が別の正常な読取を失効させる実装は不可である。

### 年間予算の保存後描画

年間予算はDB保存・結果採用に元draft/year一致を必要とする一方、保存後の通常renderはdirtyでないdraftを新しいbaselineへ交換する。この自己更新で後続の同期表示/マスタ移行候補等まで失効させてはならない。描画には開始元認証・保存operation世代・対象年の寿命を渡し、DB保存/結果採用のdraft一致条件と分離する。

BudgetSettingsの保存開始は初期無効/busy/loadingを拒否した後に既存generationを進め、前の保存後描画と新しい保存を区別する。新counterは設けない。通常renderのdraft再生成はgenerationを変えない。同じ保存の描画故障は保存済みとして通知し、再認証/年変更/新保存の開始後に戻る旧描画故障は通知しない。既存busy finallyは当該generationだけを解放する。DB/CASと保存済み原本は変更しない。

保存後描画はDB保存の成功を確認した場合だけ開始する。保存APIがrejectしたときは入力を保持して保存失敗を通知し、後続の表示故障を「保存済み」と扱わない。実IDB write abortと、もし呼ばれたら故障する描画依存を組み合わせ、原本不変・dirty入力保持・後続描画0・保存済み通知0を直接検査する。
